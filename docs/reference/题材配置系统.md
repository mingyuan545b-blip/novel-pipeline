## 一、核心设计原则

**1个题材 = 1个目录 = 唯一配置源**

所有关于某个题材的配置（角色标签、状态追踪、KV字段、配角模板、里程碑、约束、风格、检测器），只存在于一个genre目录里。其他agent不硬编码任何题材信息，全部从genre文件读取。

```
server/services/genres/
├── baseGenreTemplate.js          ← 通用基础模板（所有题材的默认值）
├── baby/                         ← 萌娃题材（继承基础模板+亲子视角）
└── high-martial-crossplane/      ← 高武穿越·诸天万界（继承基础模板+凡人修仙传级深度）
```

**题材白名单CI强制校验**：`scripts/audit-genre-whitelist.js` 在CI阶段校验，白名单外题材禁止入库。新增题材必须先过 SOP 09 第一阶段市场五问+质量门禁，再更新白名单脚本。

genreConfig.js 自动扫描 genres/ 目录，新目录放入即注册，无需手动配置。

## 二、基础模板结构（baseGenreTemplate.js）

每个genre通过 `createGenre(覆盖项)` 继承基础模板，只需覆盖自己特有的部分。

基础模板提供以下默认值：

| 字段 | 默认值 | 说明 |
|------|--------|------|
| stateSchema.protagonist | trackFields:'all', 每章更新 | 主角全量追踪 |
| stateSchema.supporting | trackFields:'important', 出场章节更新, importantFields:4个基础字段 | 配角关键字段追踪 |
| stateSchema.npc | trackFields:'basic', 出场章节更新, basicFields:3个字段 | 路人只记名字阵营职位 |
| kvImportantKeys | 6个基础字段 | KV索引关注字段 |
| characterProfile.protagonistTags | 11个标签, 400字 | 主角模板 |
| characterProfile.supportingTags | 8个标签, 250字 | 配角模板（默认标准级） |
| characterProfile.npcTags | 4个标签, 80字 | 路人模板 |
| characterProfile.supportingWriterPrinciples | 空 | 默认模板不启用配角写活原则（high-martial等深度题材才启用） |
| materialRules | 世界观/战力/伏笔各1条规则 | 素材类型规则 |
| milestones | 空 | 里程碑（题材必须覆盖） |
| pacingConfig | openingHookRange:100 | 节奏配置 |

| | 默认标准模板 | 凡人修仙传级深度模板（修仙/玄幻） |

## 四、占位符系统（promptFragments.js）

各agent的prompt模板使用 `{{占位符}}` 引用题材配置，运行时由 `render(template, genreId)` 替换。

### 可用占位符

| 占位符 | 来源 | 示例值（baby） | 示例值（high-martial-comedy） |
|--------|------|--------------------------|----------------------|
| `{{PROTAGONIST_TAGS}}` | characterProfile.protagonistTags | 11个标签换行拼接 | 同左 |
| `{{PROTAGONIST_WORD_COUNT}}` | characterProfile.protagonistWordCount | 400 | 400 |
| `{{PROTAGONIST_EXAMPLE}}` | characterProfile.protagonistExample | 示例文本 | 同左 |
| `{{SUPPORTING_TAGS}}` | characterProfile.supportingTags | 8个标签 | 13个标签 |
| `{{SUPPORTING_WORD_COUNT}}` | characterProfile.supportingWordCount | 250 | 400 |
| `{{SUPPORTING_EXAMPLE}}` | characterProfile.supportingExample | 示例文本 | 含深度维度示例 |
| `{{NPC_TAGS}}` | characterProfile.npcTags | 4个标签 | 4个标签 |
| `{{NPC_WORD_COUNT}}` | characterProfile.npcWordCount | 80 | 80 |
| `{{WORLDVIEW_RULE}}` | materialRules.worldview | 必须包含边界条件+违反后果 | 同左 |
| `{{POWER_SYSTEM_RULE}}` | materialRules.power-system | 必须包含升级条件+代价/限制 | 同左 |
| `{{FORESHADOWING_RULE}}` | materialRules.foreshadowing | 必须包含预期回收窗口+关联角色 | 同左 |
| `{{SUPPORTING_WRITER_PRINCIPLES}}` | characterProfile.supportingWriterPrinciples | 空 | 7条写活硬约束 |
| `{{SUPPORTING_ORGANIZER_DIMENSIONS}}` | characterProfile.supportingOrganizerDimensions | 空 | 6维度追踪文本 |

### 使用方式

```js
const { render, resolve, buildCreationStandards } = require('../../config/promptFragments');

// 方式1：渲染模板
const result = render('主角{{PROTAGONIST_WORD_COUNT}}字，配角{{SUPPORTING_WORD_COUNT}}字', genreId);

// 方式2：获取所有变量
const vars = resolve(genreId);
console.log(vars.SUPPORTING_WORD_COUNT);

// 方式3：构建完整创作标准
const standards = buildCreationStandards(genreId);
```

未解析的占位符保留原样（`{{UNKNOWN}}`不会被吞掉），可用于检测漏配。

## 五、各Agent引用关系

| Agent文件 | 引用方式 | 读取的题材配置 |
|-----------|---------|---------------|
| outlineGenerator.js | `render(systemTemplate, genre)` + `resolve(genre)` | 全部占位符（主角/配角/NPC标签+字数+示例+素材规则） |
| materialPromptBuilder.js | `buildCreationStandards(genreId)` | 全部占位符（创作标准模板） |
| materialOrganizer.js | `resolve(genre).SUPPORTING_ORGANIZER_DIMENSIONS` + `IS_DEPTH_PROFILE` | 配角整理维度、是否深度模板 |
| writer.js | `resolve(genre).SUPPORTING_WRITER_PRINCIPLES` | 配角写活原则（仅深度模板有值） |
| materialRegistrar.js | 直接读 `genre.characterProfile.supportingRegistrarNoteFields` | 配角Note字段列表 |
| characterStateSchemas.js | `getGenreRoleStrategy(genreId)` → 读 `genre.stateSchema` | 角色追踪策略 |
| stateKVIndex.js | `getGenreImportantKeys(genreId)` → 读 `genre.kvImportantKeys` | KV重要字段列表 |
| characterStateCache.js | trackedKeys硬编码（通用字段+5个配角维度） | 不直接读题材配置 |

## 六、数据库适配

### 不需要改表结构

所有题材特有字段存在JSON列里，数据库表结构是通用的：

| 表 | 题材适配方式 |
|----|------------|
| materials | `data TEXT(JSON)` → 题材特有字段（符咒数量/石化程度/系统等级等）存在data里 |
| state_kv_index | `dataKey TEXT` 动态 + `dataValue TEXT` → KV模式天然支持任意字段 |
| character_states | `delta TEXT(JSON)` → 任意字段变化存delta |
| character_state_cache | `stateJson TEXT(JSON)` → 任意字段快照 |
| character_binds | 通用绑定表，permanence字段，不题材相关 |
| entity_registry | roleLevel/isActive等通用字段，不题材相关 |

### 题材特有字段的完整生命周期

```
1. outlineGenerator生成素材 → content文本包含【符咒数量】等题材标签
2. outlineGenerator解析content → 正则提取字段写入state_kv_index
3. materialOrganizer整理 → 按题材的kvImportantKeys决定哪些字段重要
4. materialRegistrar注册 → 按题材的stateSchema决定配角追踪哪些字段
5. characterStateCache缓存 → trackedKeys包含题材特有字段
6. writer执笔 → 从缓存读取题材特有字段注入prompt
```

## 七、切换题材操作

### 切换已有题材

无需修改任何代码。项目创建时选择题材，系统自动通过 `detectGenre(styleProfile)` 识别，所有agent从genre文件读取配置。

### 新增题材

只需1步：创建 `server/services/genres/<新题材id>.js`

```js
const { createGenre } = require('./baseGenreTemplate');

module.exports = createGenre({
    id: 'cyber-xianxia',
    label: '赛博修仙',
    patterns: ['赛博', '修仙', '义体', '灵根'],

    // 以下按需覆盖基础模板默认值，不覆盖就用默认值

    stateSchema: {
        supporting: {
            importantFields: ['灵根型号', '义体等级', 'factionName', 'signatureDetail']
        }
    },

    kvImportantKeys: ['name', 'hp', 'combatPower', '灵根型号', '义体等级', 'factionName'],

    characterProfile: {
        supportingWordCount: 400,
        supportingWriterPrinciples: '【配角写活硬约束】...',  // 需要深度模板就填
        supportingTags: [
            '【年龄】', '【外貌】', '【性格】', '【说话语气】',
            '【核心欲望】', '【内在矛盾】', '【身份/职位】',
            '【与主角关系】', '【主角镜像】', '【标志性细节】',
            '【出场功能】', '【独立立场】', '【命运弧光】'
        ]
    },

    milestones: {
        1: '激活赛博灵根',
        5: '第一次义体飞升',
        10: '发现灵根病毒真相',
        28: '季终之战'
    },

    // 以下为题材Plugin原有字段（约束/风格/检测器等）
    foundation: { ... },
    styleProfile: { ... },
    writerHints: { ... },
    constraintPresets: { ... },
    reviewRules: { ... },
    detectors: { ... },
    interceptors: { ... }
});
```

### 验证新题材

```bash
# 1. 语法检查
node -c server/services/genres/cyber-xianxia.js

# 2. 注册检查
node -e "const g=require('./server/services/genreConfig'); console.log(g.getGenreById('cyber-xianxia')?.label)"

# 3. 占位符检查
node -e "const {resolve}=require('./server/config/promptFragments'); const v=resolve('cyber-xianxia'); console.log(v.SUPPORTING_WORD_COUNT, v.IS_DEPTH_PROFILE)"

# 4. 全模块加载检查
node -e "require('./server/services/pipeline/outlineGenerator'); require('./server/services/pipeline/steps/materialPromptBuilder'); require('./server/services/pipeline/steps/materialOrganizer'); require('./server/services/pipeline/steps/writer'); console.log('ALL OK')"
```

## 十、常见问题

### Q: 新增一个配角维度字段需要改哪些地方？

1. `baseGenreTemplate.js` → characterProfile.supportingTags 加标签
2. `characterStateSchemas.js` → BASE_STATE_FIELDS 加字段定义
3. `characterStateCache.js` → trackedKeys 加字段名
4. 不需要改数据库表结构（JSON列自动支持）

### Q: 新增一套配角深度模板需要改哪些地方？

1. 在 `baseGenreTemplate.js` 的 SUPPORTING_PROFILES 不存在了——直接在genre文件的 characterProfile 里覆盖 supportingTags/supportingWordCount/supportingWriterPrinciples 等字段
2. 不需要改其他agent——它们从genre文件动态读取

### Q: pipelineConfig.js 的里程碑配置为什么没合并到genre文件？

pipelineConfig.js 的里程碑调度逻辑涉及复杂的运行时逻辑，不仅是数据配置。当前各题材的 milestones 已合并到genre文件，但 pipelineConfig.js 的读取逻辑尚未改造。这是后续待办项。

### Q: characterStateSchemas.js 的 GENRE_SCHEMAS 为什么没删除？

GENRE_SCHEMAS 定义的是题材特有字段（如修仙的灵根/法宝，都市的职位/公司），这些字段定义用于字段类型校验和阈值配置，与 stateSchema（追踪策略）是不同维度。stateSchema 已从genre文件读取，GENRE_SCHEMAS 仍保留在 characterStateSchemas.js 中。
