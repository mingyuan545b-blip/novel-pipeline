# Novel-Pipeline 新题材定制规范 v2.0

> 本文档是给 AI 定制新题材 Plugin 的完整规范。包含系统架构、Agent职责、流水线流程、约束表结构、记忆层级、题材Plugin接口定义、现有题材示例。按此规范输出的 `.js` 文件放入 `server/services/genres/` 目录即可自动注册生效。

---

## 一、系统总览

### 1.1 流水线架构

```
用户创建项目(选择题材/模式)
    ↓
generateFromTemplate → 生成世界观/角色/大纲/章节意图
    ↓
runInfinitePipeline → 逐章循环
    ↓ 每章执行 runFullPipeline
    ↓
┌─────────────────────────────────────────────────────────┐
│  runFullPipeline（单章完整流水线）                         │
│                                                         │
│  1. chapterIntent  → 生成章节意图(goal/mustKeep/mustAvoid)│
│  2. hookBudget     → 生成伏笔议程(推进/回收/预算)          │
│  3. ruleStack      → 生成规则栈(L1-L4分层约束)            │
│  4. beatAllocator  → 分配节拍(每章3-8个节拍+技法绑定)      │
│  5. runPipelineStep → 执行Agent步骤                       │
│     ├── writer        → 生成正文                         │
│     ├── first-review  → 初审(或fast-review)              │
│     ├── second-review → 复审                             │
│     ├── final-editor  → 定稿                             │
│     ├── reviser       → 返修(审核不通过时)                │
│     ├── material-manager → 素材提取/更新                  │
│     ├── polisher      → 润色                             │
│     └── reader        → 阅读评审                         │
│  6. memory.updateAfterChapter → 更新5层记忆               │
│  7. consistency.quickCheck → 一致性检查                    │
│  8. stateSnapshot → 创建快照                              │
│  9. imageGen → 生成插图(可选)                             │
└─────────────────────────────────────────────────────────┘
```

### 1.2 模式与步骤序列

> **统一长篇模式**：系统已移除爽文(shuangwen)和番茄短篇(tomato-short)模式，所有项目统一使用长篇模式（novel）。

| 模式 | 步骤序列 | 每章最大轮次 | 目标字数 |
|------|---------|-------------|---------|
| novel（长篇） | writer → first-review → second-review → final-editor | 5 | 2200-2800 |

通过审核后追加：material-manager → polisher → reader

**注意**：fast-review Agent仍保留在AGENT_TYPES中（genreValidator.js验证），但默认流程使用first-review+second-review组合。如需启用fast-review，通过reviewOverride机制路由。

## 二、Agent职责详细定义

### 2.1 writer（执笔人）

| 属性 | 值 |
|------|---|
| 职责 | 根据大纲+素材+记忆+字数要求+题材注入生成章节正文 |
| LLM路由 | aliyunCoding（qwen3.6-plus） |
| 输出格式 | 纯文本正文，无Markdown标记 |
| 题材注入 | `writerHints.terminologyDimming` 注入到user prompt |
| 上下文 | 大纲 + 上章摘要 + 素材索引 + 记忆上下文 + 节拍分配 + 技法注入 + 章节意图 |
| 字数要求 | 由 `MODE_CONFIGS[mode]` 和 `project.wordConfig` 动态注入 |

### 2.2 first-review（初审员）

| 属性 | 值 |
|------|---|
| 职责 | 审核章节正文质量，输出Markdown报告+JSON数据块 |
| LLM路由 | aliyunCoding（qwen3.6-plus） |
| 输出格式 | Markdown报告 + 末尾JSON块 |
| 题材注入 | `reviewRules.firstReview` 的3个规则（perspectiveRule + terminologyRule + outputRule） |
| 硬拦截 | 运行 `interceptors.firstReview`，返回 hardBlockIssues/warningIssues/hints |
| 额外检测 | 告知式动词(detectTellVerbs) + 信息滴入分数(calcInfoDripScore) + 管线元数据泄漏(detectPipelineMetadataLeak) |
| JSON输出字段 | `decision`(approve/reject/revise) + `perspective`(按perspectiveSchema) + `issues[]` + `wordAssessment` + `suggestions[]` |

### 2.3 fast-review（快审员）

| 属性 | 值 |
|------|---|
| 职责 | 轻量级快速审核，可作为first-review+second-review的替代路径（通过reviewOverride路由） |
| LLM路由 | aliyunCoding（qwen3.6-plus） |
| 输出格式 | Markdown报告 + 末尾JSON块 |
| 题材注入 | `reviewRules.firstReview`（复用初审规则） |
| JSON输出字段 | 同first-review |
| 使用场景 | 默认流程不启用，通过reviewOverride机制按需路由 |

### 2.4 second-review（复审员）

| 属性 | 值 |
|------|---|
| 职责 | 对初审结果二次校验，纠正初审误判，补充遗漏 |
| LLM路由 | aliyunCoding（qwen3.6-plus） |
| 输出格式 | Markdown报告 + 末尾JSON块 |
| 题材注入 | `reviewRules.secondReview` 的3个规则（perspectiveRule + terminologyRule + correctionRule） |
| 硬拦截 | 运行 `interceptors.secondReview` |
| 额外注入 | 风格模板审核（styleTemplate） |

### 2.5 final-editor（定稿人）

| 属性 | 值 |
|------|---|
| 职责 | 综合初审+复审结果做最终approve/reject/revise判定 |
| LLM路由 | aliyunCoding（qwen3.6-plus） |
| 输出格式 | Markdown报告 + 末尾JSON块 |
| 题材注入 | `reviewRules.finalEditor.perspectiveRule` |
| 决策逻辑 | 可覆盖审核员的reject判定为approve（当认为审核矫枉过正时） |

### 2.6 reviser（返修员）

| 属性 | 值 |
|------|---|
| 职责 | 根据审核反馈修改正文 |
| LLM路由 | aliyunCoding（qwen3.6-plus） |
| 输出格式 | 纯文本正文 |
| 题材注入 | `reviewRules.reviser` 的3个规则（terminologyDimmingRule + perspectiveRule + repairRules） |
| 后处理 | 字数4重检查 + 硬性检测(_runHardBlockChecks) + 内容清洗 |

### 2.7 material-manager（素材管理器）

| 属性 | 值 |
|------|---|
| 职责 | 从章节内容提取/更新角色、关系、世界观、伏笔等素材 |
| LLM路由 | aliyunCoding（qwen3.6-plus） |
| 输出格式 | JSON（素材更新指令数组） |
| 题材注入 | `styleProfile.materialFocus`（素材关注优先级：primary/secondary/skip） |
| 素材生成规则 | `materialRules`（每种素材类型的生成规则和命名规范） |
| 素材类型 | 由题材插件的 materialFocus 动态决定，不再硬编码。primary类型必须生成，secondary按需生成，skip类型禁止生成 |

### 2.8 polisher（润色员）

| 属性 | 值 |
|------|---|
| 职责 | 文采提升，不改变剧情/人物/设定/字数 |
| LLM路由 | aliyunCoding（qwen3.6-plus） |
| 输出格式 | 纯文本正文 |

### 2.9 reader（阅读者）

| 属性 | 值 |
|------|---|
| 职责 | 阅读近14章+后续大纲，输出评审意见 |
| LLM路由 | aliyunCoding（qwen3.6-plus） |
| 输出格式 | Markdown评审报告 |

## 三、5层记忆系统

| 层级 | 常量 | 含义 | 优先级 | 衰减率 | 内容 |
|------|------|------|--------|--------|------|
| L0 | `core` | 核心设定 | 100 | 0（永不衰减） | 世界观规则 + 战力体系 + 核心人物 |
| L1 | `active` | 活跃状态 | 80 | 0.02/章 | 人物状态 + 关系状态 + 装备状态 + 成长履历 |
| L2 | `recent` | 近期上下文 | 60 | 0.05/章 | 近5章摘要 + 活跃任务 + 未回收伏笔 |
| L3 | `archive` | 归档记忆 | 40 | 0.10/章 | 相关历史章节 + 已归档素材 |
| L4 | `compressed` | 压缩卷摘要 | 20 | 0.15/章 | 每30章一卷的卷级摘要 |

## 四、约束系统

### 4.1 规则栈（4层架构）

| 层级 | 名称 | 优先级 | 作用域 | 可被覆盖 |
|------|------|--------|--------|---------|
| L1 | hard_facts | 100 | global | 不可被任何层覆盖 |
| L2 | author_intent | 80 | book | 不可被L3/L4覆盖 |
| L3 | planning | 60 | arc | 可被L4覆盖 |
| L4 | current_task | 70 | local | — |

**核心原则**：只有L4→L3允许覆盖，L1硬事实层不可被任何层覆盖。

### 4.2 约束预设

系统内置基础约束（constraintInjector.js 的 BASE_CONSTRAINT_PRESETS）：

| 约束ID | 标签 | 描述 |
|--------|------|------|
| no-derailment | 不降智 | 角色不得出现智商断崖式下降 |
| character-consistency | 角色定位一致 | 每个角色的职位、行动和说话方式必须符合自身定位 |
| anti-tool-character | 反工具人 | 配角不得仅为推动主角剧情而存在 |
| character-depth | 角色深度 | 角色必须有独立动机和内在矛盾 |
| worldview-consistency | 世界观一致 | 不出现与世界观无关的元素，所有设定必须自洽 |
| hook-every-chapter | 章末钩子 | 每章结尾必须设置悬念或钩子 |
| fast-escalation | 节奏递进 | 剧情必须持续升级（注意：甜宠/治愈类题材不适用，应通过incompatibleConstraints排除） |
| reader-satisfaction | 读者爽感 | 主角必须频繁获得成就感（注意：节奏舒缓类题材不适用，应通过incompatibleConstraints排除） |
| simple-readable-style | 简单好读 | 句子短、段落短、节奏流畅（注意：需要细腻感官描写的题材应调整） |
| face-slapping | 打脸 | 主角必须通过实力打脸质疑者（仅适用于逆袭/打脸类题材） |
| power-fantasy | 力量幻想 | 主角必须持续获得力量提升（仅适用于升级流题材） |

**题材插件可通过以下机制控制约束**：
- `constraintPresets`：扩展题材特有约束
- `incompatibleConstraints`：声明不兼容的约束ID，运行时自动过滤
- `styleProfile.constraintOverrides`：覆盖默认约束

**重要**：`incompatibleConstraints` 在 constraintInjector.js 运行时生效，确保不兼容约束不会注入到任何Agent。详见 [统一加载机制](统一加载机制.md)

### 4.3 伏笔预算系统

| 参数 | 值 |
|------|------|
| 最大活跃伏笔数 | 12 |
| 过期阈值 | 30章（统一长篇模式） |
| 紧急阈值 | 5章（统一长篇模式） |

15种伏笔类型：身份悬念、历史谜团、能力异常、角色深度、角色动机、角色变化、世界秘密、真相揭示、物品线索、能力展示、威胁逼近、同伴建立、势力博弈、伏笔铺垫、情感暗线

### 4.4 节拍分配

| 模式 | 每章节拍数 | 必须节拍 | 章末节拍 |
|------|-----------|---------|---------|
| novel（长篇） | 3-6 | setup, climax | hook |

12种节拍类型：setup, tension, escalation, climax, resolution, hook, provocation, reversal, face_slap, aftermath, twist, cliffhanger

## 六、题材Plugin完整接口定义

### 6.1 文件位置

`server/services/genres/<genre-id>.js`

文件放入后自动注册到 `GENRE_REGISTRY`，无需手动注册。

### 6.2 完整字段清单

```javascript
module.exports = {
    // ===== 必需字段 =====

    id: 'genre-id',                    // 唯一标识，小写英文+连字符
    label: '题材中文名',                // 中文标签
    patterns: ['关键词1', '关键词2'],    // isMatch()匹配关键词

    isMatch(styleProfile) {             // 自动识别函数
        const key = (styleProfile?.key || '').toLowerCase();
        const label = (styleProfile?.label || '').toLowerCase();
        const desc = (styleProfile?.description || '').toLowerCase();
        return this.patterns.some(p =>
            key.includes(p) || label.includes(p) || desc.includes(p)
        );
    },

    perspectiveSchema: {                // JSON输出中perspective字段的schema
        fields: '"perspective":"protagonist/narrator/other"',
        label: '视角：protagonist/narrator/other',
        values: ['protagonist', 'narrator', 'other']
    },

    foundation: {                       // 基础设定注入
        additionalConstraints: [        // 题材特有约束项
            { id: 'constraint-id', label: '约束标签', desc: '约束描述' }
        ],
        additionalFoundationRules: [    // 铁律文本（注入到FALLBACK_FOUNDATION的[GENRE_RULES]位置）
            '铁律1：...',
            '铁律2：...'
        ],
        systemMechanismDimming: false,  // 是否需要系统机制降维（科幻/无限流题材设true）
        systemMechanismTarget: ''       // 降维目标描述
    },

    styleProfile: {                     // 完整风格配置（核心！）
        key: 'genre-id',               // 风格标识
        label: '题材中文名',            // 风格中文标签
        povRule: '视角铁律文本',        // 视角规则（注入到所有Agent）
        dialogueRule: '对话规则文本',    // 对话规则
        behaviorRule: '行为规则文本',    // 行为规则
        toneRule: '语气规则文本',       // 语气规则
        titleRule: '章节标题命名规则',   // 标题命名规则
        reviewFocus: '关注点1|关注点2', // 审核关注点（|分隔）
        materialFocus: {                // 素材关注优先级
            primary: ['character', 'worldview'],    // 主要提取
            secondary: ['relationship'],             // 次要提取
            skip: []                                 // 跳过提取
        },
        constraintOverrides: ['hook-every-chapter'], // 覆盖的约束ID（这些约束不再重复注入）
        characterRefRules: '角色称呼规范文本'         // 角色引用规则
    },

    genreBase: {                        // 行为/语气/审核追加规则
        BEHAVIOR_APPEND: '追加行为规则文本',
        REQUIRED_CONSTRAINT_OVERRIDES: ['constraint-id'], // 必需覆盖的约束
        TONE_APPEND: '追加语气规则文本',
        REVIEW_APPEND: '追加审核关注点1|追加审核关注点2'
    },

    qualityChecks: {                    // 质量检测开关
        onomatopoeia: { enabled: false },           // 拟声词密度检测
        visualAnchors: { enabled: false },          // 视觉锚点检测
        motherChildDialogue: { enabled: false },    // 母子对话检测
        modernSlangExtra: false,                     // 额外网络用语检测
        // 可自定义检测项（无限流示例）：
        // mechanicVisualization: { enabled: true },
        // progressTracking: { enabled: true },
        // trustContract: { enabled: true },
        // cliffhangerType: { enabled: true }
    },

    writerHints: {                      // 执笔人注入提示
        terminologyDimming: '注入到writer prompt的术语降维/规则呈现规范文本',
        wordCountExpand: ['扩展建议1', '扩展建议2']  // 字数不足时的扩展建议
    },

    constraintPresets: {                 // 约束预设字典
        'constraint-id': { label: '约束标签', desc: '约束描述' }
    },

    dedupRules: [                       // prompt去重规则
        { id: 'dedup-id', pattern: /正则表达式/, keep: 'first' }
    ],

    reviewRules: {                      // ★★★ 4子项审核规则（最核心）★★★
        firstReview: {
            perspectiveRule: '初审视角感知审核规则文本',
            terminologyRule: '初审术语/机制可解性判定标准文本',
            outputRule: '初审输出要求文本'
        },
        secondReview: {
            perspectiveRule: '复审视角感知审核规则文本',
            terminologyRule: '复审术语/机制判定标准文本',
            correctionRule: '初审结果校正规则文本（防止矫枉过正）'
        },
        reviser: {
            terminologyDimmingRule: '返修时术语降维/机制呈现规则文本',
            perspectiveRule: '返修时视角感知规则文本',
            repairRules: '修复规则编号列表文本'
        },
        finalEditor: {
            perspectiveRule: '定稿视角感知规则文本'
        }
    },

    detectors: {                        // 检测器函数集合
        perspective(content, styleProfile) {
            return { isViolation: false, issues: [], hasCriticalIssue: false };
        },
        terminology(content, styleProfile) {
            return { count: 0, instances: [], violationCount: 0 };
        },
        modernSlang(content, styleProfile) {
            return { count: 0, instances: [] };
        }
        // 可扩展更多检测器
    },

    interceptors: {                     // 拦截器函数集合
        firstReview(content, styleProfile, context) {
            const hardBlockIssues = [];  // { severity: 'critical'|'high', description: '', title: '' }
            const warningIssues = [];    // { severity: 'high'|'medium'|'low', description: '', title: '' }
            const hints = [];            // string
            return { hardBlockIssues, warningIssues, hints };
        },
        secondReview(content, styleProfile, context) {
            const hardBlockIssues = [];
            const warningIssues = [];
            const hints = [];
            return { hardBlockIssues, warningIssues, hints };
        }
    },

    // ===== 可选字段 =====

    perspective: null,                  // 视角检测配置（仅萌娃类题材需要）
    // perspective: {
    //     babyNames: ['宝宝', '小宝', ...],
    //     adultContextWords: ['工作', '公司', ...],
    //     babyContextWords: ['奶', '尿', ...],
    //     ...
    // }

    techJargon: {                       // 术语降维映射表
        terms: []                       // [{from: '技术术语', to: '角色可理解的表达'}]
    }
};
```

## 八、新题材定制操作清单

### 8.1 操作流程（5步走）

```
第1步：确定素材类型 → 填 materialFocus (primary/secondary/skip)
第2步：确定Agent权限 → 填 agentMaterialAccess (10个Agent × needs+detail)
第3步：填写其余字段 → foundation/styleProfile/genreBase/reviewRules/detectors/interceptors...
第4步：运行验证 → node验证脚本，确保0错误0警告
第5步：创建项目测试 → 前端创建项目，跑Pipeline验证
```

### 8.2 第1步：确定素材类型（materialFocus）

**可用素材类型清单**（来自 `server/config/materialTypes.js` 的 VALID_MATERIAL_TYPES，共31种）：

> 说明：所有素材类型对**所有题材可用**（materialTypes.js 无题材限制）。下表"实际使用题材"列是指各题材插件的 `styleProfile.materialFocus` 中实际声明该类型为 primary/secondary 的题材，未声明的题材可按需使用但默认不生成。

| 类型 | 说明 | 实际声明使用的题材（primary/secondary） |
|------|------|---------|
| character | 角色 | 所有题材（primary） |
| worldview | 世界观 | high-martial-comedy(primary) |
| relationship | 关系 | baby(primary) |
| foreshadowing | 伏笔 | high-martial-comedy(primary或secondary) |
| catchphrase | 金句 | 无题材声明（可选） |
| famous-scene | 名场面 | 无题材声明（可选） |
| power-system | 战力/能力体系 | high-martial-comedy(primary) |
| equipment | 关键物件 | high-martial-comedy(secondary) |
| faction | 势力/组织 | 无题材声明（可选） |
| institution | 机构/组织 | high-martial-comedy(secondary) |
| character-combat | 角色战斗 | 无题材声明（可选） |
| location | 地点 | 无题材声明（可选） |
| writing-technique | 写作技法 | 无题材声明（可选） |
| craft | 技艺/功法 | 无题材声明（可选） |
| mechanism | 机制 | 无题材声明（可选） |
| sub-plane | 子平面（小世界） | 无题材声明（可选，高武题材的 HIERARCHY_RULES 支持但 materialFocus 未声明） |
| growth-history | 成长史 | 无题材声明（可选） |
| narrative-bridge | 叙事桥段 | 无题材声明（可选） |
| 其他14种扩展类型 | scene/phenomenon/organization/geography/technology/character-psychology/character-personality/character-relationship/character-dialogue/character-behavior/material/index/other | 无题材声明（materialTypes.js 支持，按需使用） |

**分类规则**：
- `primary`：题材核心素材，必须生成，详细内容
- `secondary`：题材辅助素材，按需生成，中等详细
- `skip`：题材不需要的素材，禁止生成

**示例**：
```javascript
// 萌宝题材：不需要战力体系，不需要成长史
materialFocus: {
    primary: ['character', 'relationship'],
    secondary: ['worldview', 'foreshadowing'],
    skip: ['power-system', 'growth-history']
}

// 高武跨界题材：需要战力体系和机构
materialFocus: {
    primary: ['character', 'worldview', 'power-system'],
    secondary: ['equipment', 'foreshadowing', 'institution'],
    skip: []
}
```

### 8.3 第2步：确定Agent权限（agentMaterialAccess）

**核心原则**：每个Agent的 `needs` 只能包含 primary + secondary 中的类型，绝不包含 skip 中的类型。

**10个Agent的分工和详情级别**（来自genreValidator.js的AGENT_TYPES）：

| Agent | 职责 | detail | needs范围 |
|-------|------|--------|----------|
| writer | 执笔 | full | primary + secondary 全部 |
| reviser | 返修 | full | primary + secondary 全部 |
| material-manager | 素材管理 | full | primary + secondary 全部 |
| polisher | 润色 | summary | 核心3-5种（character+worldview+题材特色） |
| intent-planner | 意图规划 | summary | 核心4-5种（character+worldview+foreshadowing+题材特色） |
| first-review | 初审 | summary | 核心4-6种（character+worldview+题材核心设定） |
| second-review | 复审 | summary | 同first-review |
| fast-review | 快审 | index | 核心2-3种（character+worldview+题材最核心） |
| final-editor | 定稿 | summary | 核心3-4种（character+worldview+foreshadowing） |
| reader | 阅读 | summary | 核心3-4种（character+worldview+foreshadowing） |

**注意**：adjuster不在AGENT_TYPES中（已移除），新题材的agentMaterialAccess只需声明上述10个Agent。

**填写模板**（以甜宠匠心为例）：
```javascript
agentMaterialAccess: {
    'writer':          { needs: ['character', 'worldview', 'relationship', 'foreshadowing', 'equipment', 'catchphrase', 'famous-scene'], detail: 'full' },
    'reviser':         { needs: ['character', 'worldview', 'relationship', 'foreshadowing', 'equipment', 'catchphrase', 'famous-scene'], detail: 'full' },
    'polisher':        { needs: ['character', 'worldview', 'relationship', 'catchphrase', 'famous-scene'], detail: 'summary' },
    'intent-planner':  { needs: ['character', 'worldview', 'foreshadowing', 'relationship', 'famous-scene'], detail: 'summary' },
    'first-review':    { needs: ['character', 'worldview', 'relationship', 'foreshadowing'], detail: 'summary' },
    'second-review':   { needs: ['character', 'worldview', 'relationship', 'foreshadowing'], detail: 'summary' },
    'fast-review':     { needs: ['character', 'worldview', 'relationship'], detail: 'index' },
    'final-editor':    { needs: ['character', 'worldview', 'relationship', 'foreshadowing'], detail: 'summary' },
    'material-manager':{ needs: ['character', 'worldview', 'relationship', 'foreshadowing', 'equipment', 'catchphrase', 'famous-scene'], detail: 'full' },
    'reader':          { needs: ['character', 'worldview', 'relationship', 'foreshadowing'], detail: 'summary' }
},
```

### 8.4 第3步：填写其余字段

| # | 步骤 | 说明 |
|---|------|------|
| 1 | 实现 `reviewRules` 的4个子项 | 这是最核心的部分，每个子项的每个字段都必须填写 |
| 2 | 实现 `detectors` 至少3个 | perspective + terminology + modernSlang |
| 3 | 实现 `interceptors` 2个 | firstReview + secondReview |
| 4 | 定义 `constraintPresets` | 题材特有的约束预设 |
| 5 | 定义 `dedupRules` | 防止prompt膨胀的去重规则 |
| 6 | 定义 `qualityChecks` | 根据题材需要启用/禁用特色检测 |
| 7 | 定义 `perspectiveSchema` | 萌娃类用baby/adult/mixed，其他用protagonist/narrator/other |
| 8 | 定义 `styleProfile` | 完整的6个规则字段(povRule/dialogueRule/behaviorRule/toneRule/titleRule/characterRefRules) |
| 9 | 定义 `genreBase` | 4个追加规则(BEHAVIOR_APPEND/TONE_APPEND/REVIEW_APPEND/REQUIRED_CONSTRAINT_OVERRIDES) |
| 10 | 定义 `incompatibleConstraints` | 排除与本题材矛盾的通用约束 |
| 11 | 定义 `requiredConstraints` | 本题材必须加载的约束 |

### 8.5 第4步：运行验证

**自动验证**：系统启动时 `createGenre()` 会自动调用 `validateGenre()` 检测：
- ❌ 必填字段缺失 → 报错
- ❌ agentMaterialAccess 缺少Agent → 报错
- ❌ needs 包含 skip 类型 → 报错（硬错误）
- ⚠️ needs 包含未在 materialFocus 中声明的类型 → 警告
- ⚠️ materialFocus 中的类型没有被任何 Agent 覆盖 → 警告
- ⚠️ 未知字段 → 警告（可能是拼写错误）

**手动验证命令**：

| # | 验证 | 命令 |
|---|------|------|
| 1 | 语法检查 | `node -c server/services/genres/<genre-id>.js` |
| 2 | 注册+验证检查 | `node -e "const g=require('./services/genres/<genre-id>'); console.log(g.id, Object.keys(g.agentMaterialAccess).length+' agents')"` |
| 3 | 完整加载检查 | `node -e "require('./index')"` |

### 8.6 第5步：创建项目测试

1. 重启服务器
2. **打开题材调试面板**（`/genre-debug`），选择新题材，逐个检查每个Agent的素材访问和提示词
3. 前端创建项目，选择对应风格配置
4. 系统自动匹配题材插件（通过 patterns 关键词）
5. 启动 Pipeline，观察日志：
   - 素材生成是否只生成了 primary + secondary 类型
   - Agent 加载的素材是否与 agentMaterialAccess 一致
   - 约束注入是否过滤了 incompatibleConstraints

### 8.7 验证检查清单

| # | 检查项 | 预期结果 |
|---|--------|---------|
| 1 | validateGenre() 输出 | ✅ 题材插件验证通过 |
| 2 | 素材库内容 | 只有 primary + secondary 类型，没有 skip 类型 |
| 3 | 素材命名 | catchphrase用金句原文、famous-scene用场景名、equipment用物件名 |
| 4 | Agent日志 | writer/reviser 加载 full 详情，fast-review 加载 index 详情 |
| 5 | 约束日志 | constraintInjector 输出 "removed N constraints (xxx)" |
| 6 | 审核日志 | interceptor 检测正常，无误杀 |
| 7 | 题材调试面板 | `/genre-debug` 页面每个Agent提示词无Error，约束正确 |
