# Novel-Pipeline 统一入口加载机制与题材插件使用指南

## 一、核心设计原则

**唯一入口**：题材插件是所有Agent行为的唯一配置源。所有Agent（执笔/审核/素材管理/意图规划）都从同一个题材插件加载规则，避免重复定义和冲突。

**三级素材分类**：
- primary：必须生成，详细内容
- secondary：按需生成，中等详细
- skip：禁止生成

**运行时过滤**：incompatibleConstraints 在 constraintInjector.js 中运行时过滤，确保题材不兼容的约束不会注入到任何Agent。

## 二、加载链路（从项目创建到Agent执行）

### 2.1 项目创建时
```
templateImporter.js → 读取 genre-profile JSON → 创建项目
  → project.styleProfile = 题材插件的 styleProfile
  → project.constraints = 题材插件的 requiredConstraints + 用户选择
  → project.wordConfig = 题材配置或默认值
```

### 2.2 素材生成时
```
infinitePipeline.js → 检测素材库为空
  → generateInitialMaterials(projectId, prompt)
    → detectGenre(project.styleProfile) → 匹配题材插件
    → 读取 genre.materialFocus (primary/secondary/skip)
    → 读取 genre.materialRules (每种素材类型的生成规则)
    → 动态构建素材类型列表和命名规则
    → 调用LLM生成素材
```

关键：generateInitialMaterials 不硬编码素材类型，完全从题材插件读取！

### 2.3 大纲生成时
```
infinitePipeline.js → 检测章节为空
  → generateChapterOutlines(projectId, prompt, count)
    → 读取项目outline + 素材库
    → 调用LLM生成章节大纲
```

### 2.4 Agent执行时（每章）
```
promptBuilder.js → getAgentPrompt(project, agentType)
  → buildFoundationPrompt() → 基座规则（所有Agent共享）
  → buildStyleInjection() → 从 project.styleProfile 注入（题材插件的 povRule/dialogueRule/behaviorRule/toneRule）
  → buildGenreInjection() → 从题材插件注入 genreBase + writerHints
  → buildConstraintInjection() → 合并 project.constraints + styleProfile.constraintOverrides
    → ★ 运行时过滤 incompatibleConstraints（题材插件声明不兼容的约束会被移除）
  → buildFlavorInjection() → 题材风味注入
  → deduplicateSystemPrompt() → 去重
```

### 2.5 审核时
```
review.js → handleFirstReview / handleFastReview / handleSecondReview
  → styleInjector.js 注入 styleProfile + reviewRules + reviewFocus
  → 题材 interceptor 运行 detectors（perspective/terminology/sweetDensity等）
  → hardBlockIssues → 直接拦截
  → warningIssues → 注入到LLM审核prompt
```

## 三、题材插件文件结构

位置：`server/services/genres/<genre-id>.js`

每个题材插件通过 `createGenre()` 创建，包含以下核心字段：

### 3.1 素材控制字段

| 字段 | 作用 | 示例 |
|------|------|------|
| materialRules | 每种素材类型的生成规则 | `{ character: '必须包含职业特征+创作风格', catchphrase: '每条金句单独一个素材！' }` |
| styleProfile.materialFocus | 三级分类 | `{ primary: ['character','relationship'], secondary: ['worldview'], skip: ['power-system'] }` |

### 3.2 约束控制字段

| 字段 | 作用 | 示例 |
|------|------|------|
| incompatibleConstraints | 运行时过滤掉的约束ID列表 | `['fast-escalation', 'power-fantasy', 'face-slapping']` |
| requiredConstraints | 题材必须加载的约束 | `['sweet-artisan-pace', 'sugar-abuse-ratio']` |
| constraintPresets | 题材自定义约束定义 | `{ 'sweet-artisan-pace': { label: '甜宠匠心节奏', desc: '...' } }` |
| styleProfile.constraintOverrides | 覆盖默认约束 | `['sweet-artisan-pace', 'artisan-chemistry']` |

### 3.3 审核控制字段

| 字段 | 作用 |
|------|------|
| reviewRules | 4个子项（firstReview/secondReview/reviser/finalEditor），每个包含perspectiveRule/terminologyRule等 |
| detectors | 检测器函数（perspective/terminology/sweetDensity/dogBloodCheck等） |
| interceptors | 拦截器函数（firstReview/secondReview），返回hardBlockIssues/warningIssues/hints |

### 3.4 写作控制字段

| 字段 | 作用 |
|------|------|
| styleProfile.povRule | 视角规则 |
| styleProfile.dialogueRule | 对话规则 |
| styleProfile.behaviorRule | 行为规则 |
| styleProfile.toneRule | 语气规则 |
| styleProfile.titleRule | 标题命名规则 |
| styleProfile.reviewFocus | 审核关注点（\|分隔） |
| writerHints | 执笔人注入提示 |
| genreBase | 行为/语气/审核追加规则 |

## 四、二级索引加载机制（Agent差异化素材加载）

不同Agent对素材的需求不同，系统采用二级索引加载：

### 4.1 第一级：素材类型过滤（按题材）

题材插件的 `materialFocus.skip` 定义了禁止类型，所有Agent都不加载这些类型的素材。

```
materialFocus.skip = ['power-system', 'growth-history']
→ writer/reviser/review/material-manager 全部不加载 power-system 和 growth-history
```

### 4.2 第二级：Agent角色差异化加载（从题材插件读取）

**每个题材插件显式声明 `agentMaterialAccess`**，定义每个Agent需要什么素材和详情级别。agentRunner.js 不再硬编码，直接从题材插件读取。

```javascript
// 题材插件中的声明（以甜宠匠心为例）
agentMaterialAccess: {
    'writer':          { needs: ['character', 'worldview', 'relationship', 'foreshadowing', 'equipment', 'catchphrase', 'famous-scene'], detail: 'full' },
    'reviser':         { needs: ['character', 'worldview', 'relationship', 'foreshadowing', 'equipment', 'catchphrase', 'famous-scene'], detail: 'full' },
    'polisher':        { needs: ['character', 'worldview', 'relationship', 'catchphrase', 'famous-scene'], detail: 'summary' },
    'fast-review':     { needs: ['character', 'worldview', 'relationship'], detail: 'index' },
    // ... 共10个Agent
}
```

**核心原则**：needs 只能包含 primary + secondary 中的类型，绝不包含 skip 中的类型。validateGenre() 启动时自动检测违规。

### 4.3 详情级别说明

| 级别 | 截断长度 | 适用场景 |
|------|---------|---------|
| **full** | 不截断 | writer/reviser/material-manager |
| **summary** | 200字/条 | review/polynomial/reader |
| **index** | 60字/条 | fast-review |

### 4.4 实现位置

- **agentRunner.js**：从题材插件的 `agentMaterialAccess` 读取每个Agent的素材访问权限
- **writer.js**：`filteredActiveMats` 过滤skip类型 + `coreSettingTypes` 从题材插件动态读取核心设定类型
- **baseGenreTemplate.js**：`validateGenre()` 启动时自动验证 agentMaterialAccess 的完整性和正确性

## 六、踩坑记录（2026-05-31 per-genre显式声明改造）

### 6.1 AGENT_MATERIAL_ACCESS硬编码导致题材素材泄漏（已修复）
- **症状**：甜宠题材的writer被分配了power-system/craft/mechanism/sub-plane等不需要的素材类型
- **根因**：agentRunner.js硬编码了AGENT_MATERIAL_ACCESS，包含15种素材类型，靠skip过滤是"先全给再删"
- **修复**：删除硬编码，改为从题材插件的agentMaterialAccess读取。每个题材显式声明每个Agent需要什么素材
- **文件**：server/services/pipeline/agentRunner.js

### 6.2 题材插件配置无验证（已修复）
- **症状**：题材的needs包含skip中的equipment，materialFocus类型无Agent覆盖
- **根因**：没有启动时验证机制，配置错误无法自动发现
- **修复**：baseGenreTemplate.js新增validateGenre()，启动时自动检测：必填缺失→报错、needs含skip→报错、类型遗漏→警告
- **文件**：server/services/genres/baseGenreTemplate.js

### 6.3 incompatibleConstraints 运行时过滤缺失（已修复）
- **症状**：甜宠题材项目仍然被注入了 fast-escalation/reader-satisfaction/face-slapping 等玄幻约束
- **根因**：constraintInjector.js 只在 templateImporter.js 创建项目时过滤 incompatibleConstraints，运行时从未过滤
- **修复**：constraintInjector.js 的 buildConstraintInjection() 中添加了运行时过滤逻辑
- **文件**：server/services/prompts/constraintInjector.js

### 6.4 FALLBACK_FOUNDATION 硬约束与题材冲突（已修复）
- **症状**：审核持续以"段落超150字"为由拦截，但甜宠题材需要感官描写
- **根因**：promptBuilder.js 的 FALLBACK_FOUNDATION Rule 10 硬编码"每段不超150字"，Rule 13 硬编码"3章出金手指"
- **修复**：Rule 10 改为灵活节奏指导，Rule 13 改为题材适配节奏，删除金手指/打脸硬约束
- **文件**：server/services/prompts/promptBuilder.js

### 6.5 素材生成硬编码9种类型（已修复）
- **症状**：甜宠题材生成了 power-system（战力体系）和 growth-history（成长史），完全不需要
- **根因**：generateInitialMaterials() 硬编码了9种素材类型，不读取题材插件的 materialFocus
- **修复**：改为从题材插件动态读取 primary/secondary/skip，skip类型不出现在prompt中
- **文件**：server/services/pipeline/outlineGenerator.js

### 6.6 素材命名无标准（已修复）
- **症状**：catchphrase素材叫"经典台词集"（5条塞一起），foreshadowing叫"伏笔设计方案"（一锅炖）
- **根因**：TYPE_DESCS太笼统，LLM不知道怎么命名和拆分
- **修复**：新增 TYPE_NAMING_RULES，强制catchphrase用金句原文命名、famous-scene用场景名、foreshadowing用伏笔名，每个必须独立素材
- **文件**：server/services/pipeline/outlineGenerator.js

### 6.7 题材插件 detector 过于严格（已修复）
- **症状**：modernSlang detector 把网络用语标记为 hardBlock，sweetDensity 糖点为0就 hardBlock
- **根因**：detector 的 isViolation 返回 true 导致直接拦截，但有些情况应该让LLM做最终判断
- **修复**：modernSlang 网络用语降为 warning，sweetDensity/artisanSensory 的 isViolation 改为 false
- **文件**：已随低俗题材一并清理

### 6.8 素材生成时机错误（已修复）
- **症状**：Pipeline启动后素材库为空，但章节已开始处理
- **根因**：素材生成逻辑嵌套在 chapters.length === 0 条件内，大纲生成后条件不满足
- **修复**：素材生成逻辑移到 chapters.length === 0 条件之前，独立判断
- **文件**：server/services/pipeline/infinitePipeline.js

### 6.9 buildFoundationPrompt 返回非字符串（已修复）
- **症状**：genre-debug API的prompt预览返回 `[Error: getFoundationPrompt(...).replace is not a function]`
- **根因**：`getFoundationPrompt()` 从PostgreSQL store获取的 `foundations[0].content` 可能是非字符串对象，直接调用 `.replace()` 报错
- **修复**：`buildFoundationPrompt()` 中添加类型保护：`if (typeof raw !== 'string') raw = raw ? JSON.stringify(raw) : FALLBACK_FOUNDATION`
- **文件**：server/services/prompts/promptBuilder.js

### 6.10 genre-debug API路由被agents router的参数路由拦截（已修复）
- **症状**：`GET /api/agents/genre-debug/xxx` 返回前端HTML而非JSON
- **根因**：agents router 的 `/:type` 参数路由匹配了 `genre-debug`，优先于固定路由
- **修复**：genre-debug路由从agents router移出，直接定义在index.js中，挂载路径改为 `/api/genre-debug/`
- **文件**：server/index.js

### 6.11 旧服务器进程占端口导致新服务器静默失败（踩坑）
- **症状**：重启服务器后API仍返回旧数据，新路由404
- **根因**：StopCommand只终止shell会话，node子进程仍在监听端口。新服务器绑定端口失败但无报错
- **排查**：`netstat -ano | findstr ":3001"` 发现旧PID仍在监听
- **修复**：`Stop-Process -Id <PID> -Force` 杀掉旧进程后再重启
- **教训**：每次重启服务器前必须确认旧进程已完全退出

## 七、题材调试面板

### 7.1 功能说明

前端提供了题材调试面板（`/genre-debug`），可以在浏览器中实时查看每个题材下每个Agent的：
- 素材访问配置（needs/detail/loadedTypes/skippedTypes）
- 约束信息（requiredConstraints/incompatibleConstraints）
- 完整提示词预览（foundation + constraints + genreInjection + fullPreview）

### 7.2 API端点

| 端点 | 说明 |
|------|------|
| `GET /api/genre-debug/list` | 列出所有已注册题材 |
| `GET /api/genre-debug/:genreId/agents` | 获取题材下所有Agent的素材访问配置 |
| `GET /api/genre-debug/:genreId/:agentType/prompt` | 获取指定Agent的完整提示词预览 |

### 7.3 使用方式

1. 启动后端服务器和前端dev server
2. 浏览器打开 `http://localhost:5173/genre-debug`
3. 左侧选择题材，右侧查看Agent列表
4. 点击Agent卡片展开提示词预览
5. 提示词分为4个部分：Foundation（基座）、Constraints（约束）、Genre Style（题材注入）、Full Preview（完整预览）

### 7.4 验证清单

| # | 检查项 | 预期 |
|---|--------|------|
| 1 | 题材列表显示11个题材 | ✅ |
| 2 | 每个题材显示10个Agent | ✅ |
| 3 | Agent的loadedTypes不包含skip类型 | ✅ |
| 4 | Foundation提示词无 `[Error]` | ✅ |
| 5 | Constraints包含题材的requiredConstraints | ✅ |
| 6 | GenreInjection包含题材铁律+约束+风格规范 | ✅ |
| 7 | FullPreview = Foundation + Constraints + GenreInjection | ✅ |

## 八、新增题材的操作步骤

1. 在 `server/services/genres/` 创建 `<genre-id>.js`，用 createGenre() 定义
2. **必填**：配置 materialFocus（primary/secondary/skip）
3. **必填**：配置 agentMaterialAccess（10个Agent × needs+detail）
4. 配置 incompatibleConstraints（排除与本题材矛盾的通用约束）
5. 配置 requiredConstraints（本题材必须加载的约束）
6. 实现 reviewRules 的4个子项
7. 实现 detectors 和 interceptors
8. 运行验证：`node server/scripts/verify-agent-loading.js`
9. 重启服务器，题材自动注册（validateGenre自动检测配置完整性）
10. **打开题材调试面板**（`/genre-debug`）验证每个Agent的素材访问和提示词
11. 创建项目时选择对应风格配置，系统自动匹配题材插件
