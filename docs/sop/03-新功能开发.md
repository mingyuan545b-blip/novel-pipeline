# 新功能开发SOP

> 触发条件：新增模块/API/组件/服务
> 前置：已读 [00-陷阱清单.md](00-陷阱清单.md)

---

## 一、需求分析阶段

### 1.1 归属确认（强制）
新增功能前必须先回答：
```
[归属分析]
1. 这个功能属于哪一层？（配置/数据/服务/路由/前端组件）
2. 应该放在哪个现有模块？还是需要新建模块？
3. 涉及哪些现有文件？（grep验证依赖）
4. 是否需要数据库变更？（是→转 sop/05-数据库变更.md）
5. 是否涉及Pipeline/Agent？（是→转 sop/07-Pipeline变更.md）
```

### 1.2 禁止往主组件加代码
- 新增功能必须先确认属于哪个子组件/hook
- React组件超过5个useState必须提取自定义hook
- 主组件只做组装，业务逻辑下沉到子模块

## 二、配置统一管理

### 2.1 后端配置
- 系统常量 → `server/config/systemConfig.js` 的 `LLM_DEFAULTS`/`PIPELINE`/`AGENT_DEFAULTS`
- 题材配置 → `server/config/genreDefaults.js`
- 配置项元数据 → `server/config/configManifest.js`
- 禁止硬编码：魔法数字、URL、超时、端口、UUID

### 2.2 前端配置
- API方法 → `client/src/services/api/pipelineApi.js`（或对应api文件）
- 常量 → 对应page目录下的 `constants.js`
- Tab注册 → `client/src/pages/entitycenter/constants.js` 的 `TABS` 和 `TAB_GROUPS`

### 2.3 数据源统一管理
- 新表必须注册到 `server/db/pgConstants.js` 的 `DEDICATED_TABLES` + `TABLE_ALIASES`
- 新表必须有专用写入handler（见 sop/05-数据库变更.md）
- store类型必须注册到 `server/store.js` 的 `VALIDATED_TYPES`（如需验证）

## 三、后端开发清单

### 3.1 服务模块（≤200行）
```
server/services/<module>/
├── <module>Constants.js    — 常量+枚举+工厂函数+校验
├── <module>Module.js       — CRUD业务逻辑
└── <module>Helpers.js      — 辅助函数（可选）
```

### 3.2 路由（≤200行）
```
server/routes/<module>Routes.js
- router.get('/<module>/:projectId', ...)
- router.post('/<module>/:projectId', ...)
- 在server/index.js注册：app.use('/api/pipeline', require('./routes/<module>Routes'))
```

### 3.3 LLM提取器扩展（如需）
- 扩展对应extractor的SYSTEM_PROMPT
- 扩展parseResponse解析新字段
- 扩展empty对象默认值
- 扩展extractAndSave存储逻辑

## 四、前端开发清单

### 4.1 组件结构（≤200行/≤5个useState）
```
client/src/pages/<page>/
├── <Module>Tab.jsx         — 主组件（只做组装）
├── <Module>Form.jsx        — 表单组件
├── <Module>List.jsx        — 列表组件
├── use<Module>.js          — 自定义hook（状态逻辑）
├── <module>Constants.js    — 前端常量
└── <module>.css            — 样式（禁止内联style）
```

### 4.2 API方法
在 `pipelineApi.js` 新增方法：
```js
getModule: (projectId) => api.get(`/pipeline/<module>/${projectId}`),
createModule: (projectId, payload) => api.post(`/pipeline/<module>/${projectId}`, payload),
```

### 4.3 UI规范
- 禁止内联style，使用CSS模块
- 高对比度配色（参考现有 neon-* 变量）
- 字体最小13px（防止看不清）
- 思维导图式分组（参考TAB_GROUPS）
