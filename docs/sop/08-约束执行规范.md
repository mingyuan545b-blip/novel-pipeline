# 约束执行规范（CES - Constraint Enforcement System）

> **触发条件**：任何约束词/审核/override/hardBlock相关变更
> **核心目标**：用少量元约束覆盖大范围问题，支撑300万字长篇不退化
> **前置**：已读 [00-陷阱清单.md](00-陷阱清单.md)（特别关注#42-#44）

---

## 一、设计哲学

### 1.1 当前问题（补丁式陷阱）

当前约束体系是"词级补丁"：
- 约束词细到"禁止仿佛/宛如/似乎/不禁/一抹"（10+个词级约束）
- 检测靠关键词匹配（`/仿佛|宛如|似乎/`）
- override靠关键词判断（"原文有仿佛=视角误判"）
- hardBlock覆盖面窄（只查7类）

**300万字后必然退化**：
- 约束词膨胀 → prompt过长 → LLM约束疲劳 → 执行率下降
- 关键词检测 → LLM换词绕过（"仿佛"→"好像"→"犹如"）→ 检测失效
- override关键词 → "仿佛"成免死金牌 → 审核失效

### 1.2 新体系原则（元级规范）

**元约束 > 词级约束**：1个元约束覆盖10+个词级约束
**模式识别 > 关键词匹配**：检测"比喻词替代感官"模式，而非"仿佛"一词
**规则判断 > 关键词判断**：override基于"主语是否主角"规则，而非"是否有仿佛"
**反馈闭环 > 静态约束**：执行率自动反馈，约束权重动态调整

## 二、约束词三级分类（Constraint Tiering）

### 2.1 T0-元约束（Meta-Constraint）

| 属性 | 说明 |
|---|---|
| 数量上限 | 5-8个（少而精） |
| 覆盖范围 | 大范围问题模式 |
| 执行机制 | 自动模式检测 + LLM审核双保险 |
| 阻断级别 | hardBlock |

**T0元约束清单**（定义在 constraintMetaSpec.js）：

| ID | 元约束 | 覆盖的词级约束 | 检测模式 |
|---|---|---|---|
| M1 | 禁止用比喻词/程度副词/量词堆砌替代具体感官描写 | 仿佛/宛如/似乎/不禁/一抹/不由/一丝/一缕 | 统计比喻词密度，单章>5次=违规 |
| M2 | 每章冲突解决方式必须与前N章不同（N=⌊章节号/10⌋+1） | 机械式打脸/被动出手→意外效果→装逼收工 | 提取冲突解决模式，比对前N章 |
| M3 | 本章开头必须承接前一章结尾的最后场景/动作/对话 | 章节衔接断裂 | 比对前章结尾200字与本章开头200字 |
| M4 | 禁止用抽象抒情/哲学概括替代具体场景 | 时间仿佛静止/空气凝固/这就是命运 | 检测抽象抒情句式模式 |
| M5 | 配角必须展现独立于主角的动机/特质 | 工具人化/只说"是""好的" | 统计配角台词中工具性台词占比 |

### 2.2 T1-硬约束（Hard-Constraint）

| 属性 | 说明 |
|---|---|
| 数量上限 | 10-15个 |
| 覆盖范围 | 格式/字数/视角/命名/红线 |
| 执行机制 | hardBlock自动检测 |
| 阻断级别 | hardBlock |

**T1硬约束清单**（定义在 constraintHardSpec.js）：

| ID | 硬约束 | 检测方式 |
|---|---|---|
| H1 | 字数下限/上限 | 系统统计 |
| H2 | 角色名锁定（素材库为准） | 名称匹配 |
| H3 | 视角锁定（主角限知） | 主语+内心陈述检测 |
| H4 | 管线元数据禁止泄露 | 正则匹配 |
| H5 | 敏感词拦截 | 敏感词库 |
| H6 | 跨章文本重复 | 相似度检测 |
| H7 | 网络用语/现代俚语 | 词汇库匹配 |

### 2.3 T2-软约束（Soft-Constraint）

| 属性 | 说明 |
|---|---|
| 数量上限 | 20-30个 |
| 覆盖范围 | 风格/节奏/技法 |
| 执行机制 | 审核员判断 + 反馈闭环 |
| 阻断级别 | 累计3次=升级为block |

**T2软约束清单**（定义在 constraintSoftSpec.js）：

| ID | 软约束 | 反馈机制 |
|---|---|---|
| S1 | 段落长短交替 | 审核员判断 |
| S2 | 展示代替告知 | detectTellVerbs |
| S3 | 章末钩子张力 | extractEndingTension |
| S4 | 系统人格一致性 | 审核员判断 |
| S5 | 信息注入节奏 | calcInfoDripScore |

## 三、执行反馈闭环（Feedback Loop）

### 3.1 执行率统计

每章生成后，`constraintFeedbackCollector.js` 自动统计：

```javascript
{
    chapterNumber: 5,
    constraintStats: {
        'M1': { executed: true, violations: 2, rate: 0.8 },
        'M2': { executed: true, violations: 0, rate: 1.0 },
        'M3': { executed: false, violations: 1, rate: 0.0 },
        'H2': { executed: true, violations: 0, rate: 1.0 },
        'S4': { executed: false, violations: 1, rate: 0.0 }
    },
    cumulativeStats: {
        'M1': { recent3Rate: 0.7, totalRate: 0.85 },
        'S4': { recent3Rate: 0.0, totalRate: 0.3 }  // 连续3章未执行
    }
}
```

### 3.2 动态权重调整

```javascript
// constraintWeightResolver.js
function resolveConstraintWeight(constraintId, cumulativeStats) {
    const stats = cumulativeStats[constraintId];
    if (!stats) return 1.0;  // 默认权重

    // 执行率<80%，权重提升1.5倍
    if (stats.recent3Rate < 0.8) return 1.5;

    // 执行率>95%，权重降低0.8倍（已内化）
    if (stats.recent3Rate > 0.95) return 0.8;

    // 连续3章执行率<60%，升级为hardBlock
    if (stats.recent3Rate < 0.6) return 'ESCALATE_TO_HARD_BLOCK';

    return 1.0;
}
```

### 3.3 反馈注入

下一章的prompt自动注入"上章约束执行反馈"：

```
## 上章约束执行反馈（自动生成）
- M1（禁止比喻词替代感官）：上章违规2次，本章权重×1.5
- M3（章节衔接）：上章违规1次，本章权重×1.5
- S4（系统人格一致性）：连续3章未执行，已升级为hardBlock
```

## 四、override治理规范（Override Governance）

### 4.1 override必须基于规则而非关键词

**禁止**：
```javascript
// 补丁式：基于关键词
if (hasSpeculation || hasExternalExpression) {
    return { override: true };  // "仿佛"成免死金牌
}
```

**规范**：
```javascript
// 规范式：基于规则
function shouldOverridePerspectiveViolation(issue, chapterContext) {
    // 规则1：主语必须是主角
    const isProtagonistSubject = checkSubject(issue.originalText, chapterContext.protagonistName);
    if (!isProtagonistSubject) return false;

    // 规则2：不能直接陈述NPC内心
    const directlyStatesInnerState = /觉得|感到|心想|暗想|内心/.test(issue.originalText);
    if (directlyStatesInnerState) return false;

    // 规则3：必须是外部观察或主观推测
    const isExternalObservation = checkExternalAction(issue.originalText);
    const isSubjectiveInference = checkInferenceMarker(issue.originalText);

    return isExternalObservation || isSubjectiveInference;
}
```

### 4.2 override累计治理

```javascript
// overrideGovernance.js
function checkOverrideEligibility(issueType, projectId, store) {
    const recentOverrides = await getRecentOverrides(projectId, issueType, 3);

    // 同一类问题连续3章被override，第4次禁止override
    if (recentOverrides.length >= 3) {
        return {
            eligible: false,
            reason: `同类问题[${issueType}]连续3章被override，本次禁止override，必须修复`
        };
    }

    return { eligible: true };
}
```

### 4.3 override日志规范

每次override必须记录到audit日志：

```javascript
{
    action: 'review:override',
    projectId,
    chapterNumber,
    issueType: 'perspective-violation',
    overrideReason: '主语为主角+外部观察+无直接内心陈述',
    cumulativeCount: 2,  // 累计override次数
    governanceStatus: 'eligible'  // eligible | blocked
}
```

## 五、约束词精简规范（Constraint Distillation）

### 5.1 精简原则

**1个元约束覆盖10+个词级约束**：

| 词级约束（废弃） | 元约束（保留） |
|---|---|
| 禁止"仿佛" | M1: 禁止用比喻词替代具体感官描写 |
| 禁止"宛如" | M1 |
| 禁止"似乎" | M1 |
| 禁止"不禁" | M1 |
| 禁止"一抹" | M1 |
| 禁止"时间仿佛静止" | M4: 禁止抽象抒情替代具体场景 |
| 禁止"空气凝固" | M4 |
| 禁止"这就是命运" | M4 |
| 禁止"机械式打脸" | M2: 冲突解决方式必须与前N章不同 |
| 禁止"被动出手→意外效果→装逼" | M2 |

### 5.2 prompt膨胀控制

**约束词总量控制**：
- T0元约束：5-8个，约500字
- T1硬约束：10-15个，约800字
- T2软约束：20-30个，约1200字
- **总约束词上限：2500字**（超过必须精简）

**动态加载**：
- T0元约束：每章必载
- T1硬约束：每章必载
- T2软约束：按题材/章节进度选择性加载

## 六、检测模式规范（Detection Pattern）

### 6.1 模式识别 > 关键词匹配

**禁止**：关键词匹配（LLM换词绕过）
```javascript
// 补丁式：关键词匹配，LLM换"仿佛"→"好像"即可绕过
const AI_WORDS = /仿佛|宛如|似乎|不禁/;
```

**规范**：模式识别（覆盖同类变体）
```javascript
// 规范式：词性模式识别
function detectMetaphorSubstitution(text) {
    // 模式：[比喻词] + [抽象名词] 替代 [具体感官描写]
    const metaphorPattern = /(?:仿佛|宛如|似乎|犹如|恰似|宛若|好似|好像|一如|恍若|像是|如同)[^，。！？]{2,15}[般|样|的|一般]/g;
    // 模式：[程度副词] + [动词] 替代 [具体动作]
    const adverbPattern = /(?:不禁|不由|不由自主|情不自禁|默默|静静|缓缓|淡淡|微微|悄然|蓦地)[^，。！？]{1,10}[动词]/g;
    // 模式：[量词] + [抽象名词] 替代 [具体量词]
    const quantifierPattern = /(?:一丝|一缕|一抹|一瞬|一刹那|一瞬间|一分|一毫)[^，。！？]{1,8}[感觉|气息|意味|神色|情绪|笑意|寒意|暖意]/g;

    return { metaphor: metaphorPattern, adverb: adverbPattern, quantifier: quantifierPattern };
}
```

### 6.2 检测函数注册规范

每新增T0/T1约束，必须同步注册检测函数：

```javascript
// constraintDetectionRegistry.js
const DETECTION_REGISTRY = {
    'M1': { fn: detectMetaphorSubstitution, threshold: 5, block: true },
    'M2': { fn: detectConflictPatternRepeat, threshold: 1, block: true },
    'M3': { fn: detectChapterCoherence, threshold: 0, block: true },
    'M4': { fn: detectAbstractSentiment, threshold: 2, block: true },
    'M5': { fn: detectToolCharacter, threshold: 0.5, block: true },
    'H1': { fn: detectWordCount, threshold: 'config', block: true },
    // ...
};
```
