# SOP 11 — 数据备份与恢复

> 触发：2026-09-30 外部评审指出「1700 章、1.7 亿 token 的成果，数据库零备份」。
> 现状核对：`backups/` 此前只有一份 2026-05-21 的目录，全仓库无任何 `pg_dump` 调用。

## 一、为什么必须做

单个四~五百万字连载项目 ≈ **1700 章、约 1.7 亿 tokens** 的产出，全部落在 PG 的 40 张表里。
数据库损坏 / 误删项目 / 迁移脚本写错，都是**一次事件全量归零**，且无法用代码回滚。
备份是唯一"一失全失"风险的解药，优先级高于任何功能开发。

## 二、交付物

| 文件 | 作用 |
|------|------|
| `scripts/pgBackup.js` | CLI：备份 / 校验 / 恢复演练 / 保留策略 |
| `scripts/lib/pgBackupCore.js` | 核心逻辑（pg_dump 自动发现、导出、sha256、保留、恢复） |
| `scripts/pgBackupTask.bat` | Windows 外壳，供任务计划调用（带日志） |
| `scripts/registerBackupTask.ps1` | 注册"每日备份"计划任务（**需用户显式执行**） |
| `tests/unit/pgBackup.test.js` | 核心逻辑单测（18 例） |
| `backups/pg/` | 产物目录（**已在 .gitignore，不入库**） |

## 三、常用命令

```bash
npm run backup:dry            # 干跑：只体检 pg_dump/连接/目录，不落盘
npm run backup                # 备份 + 保留策略（默认保留最近 14 份）
npm run backup:list           # 列出已有备份（大小/表数/时间）
npm run backup:verify         # 校验最新一份：存在性 + 大小 + sha256
npm run backup:restore-test   # 恢复演练：建临时库→恢复→比对行数→删临时库
node scripts/pgBackup.js --keep 30 --out D:/pgbak   # 自定义保留份数/异地目录
```

**强烈建议 `--out` 指到另一块物理盘或网络盘**：同一个盘坏掉时，备份与数据一起没。

## 四、产物结构

```
backups/pg/backup-YYYYMMDD-HHmmss/
├── dump.pgc        # pg_dump 自定义格式（-Fc，压缩，可 pg_restore 选择性恢复）
└── manifest.json   # bytes / sha256 / 40 张表的行数基线 / 时间 / pg_dump 路径
```

manifest 里的**行数基线**是恢复演练的判据：恢复后逐表比对，不一致即判定备份不可用。

## 五、定时任务（Windows）

```powershell
# 1) 注册（当前用户，无需管理员；默认每日 03:30）
powershell -ExecutionPolicy Bypass -File scripts\registerBackupTask.ps1
powershell -ExecutionPolicy Bypass -File scripts\registerBackupTask.ps1 -Time 04:15

# 2) 立即验证
schtasks /Run /TN "NovelPipeline-PG-Backup"
node scripts/pgBackup.js --list

# 3) 卸载
Unregister-ScheduledTask -TaskName "NovelPipeline-PG-Backup" -Confirm:$false
```

日志落在 `backups/pg/_logs/backup.log` 与 `backup.err.log`。

> ⚠️ 注册计划任务属于系统级改动，按项目约定**由用户显式执行**，不自动安装。

## 六、恢复演练（每季度至少一次）

```bash
npm run backup:restore-test
```

流程：连 `postgres` 库 → `CREATE DATABASE novel_pipeline_restore_check` →
`pg_restore` 导入 → 逐表比对行数 → `DROP DATABASE ... WITH (FORCE)`。
临时库名固定，演练不触碰生产库。

**只备份不演练 = 没备份**。备份文件损坏（磁盘坏道/中断）只有恢复时才会暴露。

## 七、坑与约束

1. **pg_dump 不在 PATH**：实测本机 PostgreSQL 17 装在 `C:/Program Files/PostgreSQL/17/bin`
   但不在 PATH。脚本会自动扫描标准安装目录；也可用环境变量 `PG_DUMP_PATH` / `PG_RESTORE_PATH` 显式指定。
2. **口令只走 `PGPASSWORD`**：绝不进命令行参数（进程列表可见）。
3. **一律 `-w`（--no-password）**：避免自动化流程卡在交互式口令提示上；口令缺失时快速失败并给出指引。
4. **不能用 `dbname` 连接串删自己**：删/建临时库必须连到 `postgres` 库执行。
5. **保留策略按目录名排序**（`backup-YYYYMMDD-HHmmss` 天然可比），删除是整目录 `rm -rf`，含 manifest。
6. **`.env` 用 `override: true`**：与项目约定一致，避免用户级旧环境变量遮蔽项目配置。
