> 关系、摘要、状态追踪。用户已授权全权执行（含"道具一次性/伏笔语义、关系复合"等产品决策按建议落地）。

## 数据模型勘实（决定实现方式）

- `item-definitions`：`defType/rarity/tags/sourceChapter/brief~loreDesc/propertiesJson/constraintsJson`；
  **无**"一次性/消耗/生命周期"字段 → 一次性/伏笔语义需新增字段；名称自带**归属前缀**（`苍生簿·`/`白事堂·`）。
- `entity-relations`：`relType/relLabel/strength/trustLevel/startChapter/endChapter/isSecret/notes`，
  且 `addRelation` 按 (from,to,relType) 去重 → **同一对角色可挂多条不同类型关系边**（复合关系主要是前端聚合）。
- 本项目 27 个 item-definitions 全为 equipment、0 technique。

### P3 世界域：归属归一 + 可读化（已完成）

根因（实测）：19 条 world-info + 137 条 entity-scope 的 `worldId` **恒为 `main-world`**，真正区分世界的是
`worldName`；同一世界跨章被反复描述（名称带括号/斜杠后缀）→ 卡片"0 归属、大杂烩"。另 WorldCard 读的是
`entityName/status`，实际字段是 `name/isVisitor` → 实体名空白、穿越统计错。

- 新增 `worldScopeUtils.js`：`baseWorldName` 归一去重、`buildWorlds`（同世界保留信息最全的一条）、
  `buildEntityIndex`（按归一名聚合，兼容 name/entityName）、`shapeWorlds`（搜索/排序/仅有归属）
- 抽离 `WorldCard.jsx`（原 WorldScopeComponents 已 195/200 行）：字段修正 + **类型 chips** + 按类型分组 + 长列表折叠
- `useWorldScope` 改用 utils 聚合；`WorldScopeTab` 加 搜索 / 归属数排序 / 仅有归属 工具条

实测：11 个世界、137 实体归位，归属数 56/32/9/7/8/6/5…（不再 0），搜索"苍生"→2，console 0 报错。

### P6 人物关系网络图 + 世界域去重（已完成，用户反馈后返工）

用户反馈"关系还是换汤不换药"，要求像参考图那样的**人物关系图**：中心人物 + 放射状带标签箭头，**点谁谁变中心展开**。

- **自研 SVG 关系图**（无第三方图库）：
  - `relationGraphLayout.js`（纯函数）：按关系类型聚簇 + 环上布局（同类型相邻、簇间留白；>14 节点内外环交错）；
    多条边做垂直微偏移避免重叠
  - `RelationGraphView.jsx`：中心节点 + 放射节点 + 带箭头/标签的边（按类型着色，虚线=对方指向中心）、
    图例、复合节点更大并标"N 条"；**点击任一节点即以他为中心重新展开**，带「← 返回」栈
  - `relationGraph.css`
  - `EntityGraph` 增加「关系图」模式并设为默认（与「复合视图」「中心视图」并存）
- **世界域角色重复**：同一实体按章重复登记（实测"沈砚"在某世界出现 7 次，50→唯一 38）→
  `buildEntityIndex` 按 (类型,名字) 合并，保留 `firstChapter/lastChapter`；卡片显示 `Ch2–16`。
  全局实体 137 → **112**（去重 25）。
- **顺带修**：关系里同一人物存在**多套 id**（legacy UUID 与 character-xxx）导致图上出现两个"柳三娘"

实测（Playwright）：关系图默认中心=连接数最多者（沈砚，10 节点/19 边）；点「白主簿」→ 中心切换为白主簿（1 节点）；
「← 返回」回到沈砚；console 0 报错。
