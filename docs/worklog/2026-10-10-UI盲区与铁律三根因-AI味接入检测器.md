## 一、UI 盲区（用户被卡住的主因）

**先判性质：是数据还是 UI？** 取证（项目 `万界副本·博弈者` 8bc180d6）：
- 章节表：`secondReviewOutput` 含"铁律三"的**只有第 1、6 章**；第 2 章是正常的逐章复审（内容各异）→ **数据没问题**。
- 流水线日志表：`pipeline-logs` 里"铁律三"也只落在第 1、6 章。

**→ 结论：UI 渲染 bug。** 根因在 `client/src/pages/pipeline/usePipelinePageState.js`，两处叠加：
1. **状态轮询恒覆盖**：`usePipelineStatus` 每 3s 拉 `/pipeline/infinite/status`（**项目级**历史日志），
   空闲时也 `setPipelineState({logs: mapInfiniteLogs(...)})` → 执行日志面板恒被项目级日志覆盖。
2. **"仅空时加载"守卫**：`loadPipelineLogs` 里 `if (entries.length>0 && pipelineState.logs.length===0)` ——
   首次加载后 logs 非空，**再点任何章节都不刷新** → 面板永远停留在第一条（第 1 章的元数据泄露）。

**修复**（`usePipelinePageState.js`）：
- 状态轮询：**只在 running 时**用项目级实时日志覆盖；空闲不复写 logs（保留"所选章节"的日志）。
- `loadPipelineLogs`：去掉"仅空时加载"守卫；运行中不加载章节历史；空闲时点哪章加载哪章。

**顺手修掉一个潜伏 bug（"偷懒点"）**：同文件第 147 行用了 `STATUS_VALUES` 却**从未 import**
（`rerunMaterialManager`「补跑素材管理员」一按必 `ReferenceError` 静默失败）。
baseline lint 同样报错 → 既存潜伏。已改为从单一源 `./pipelineConstants` 导入。

## 二、铁律三根因（幽灵规则 + 误报）

**什么是铁律三**：审稿器 `genres/high-martial-crossplane/interceptors.js` 引用的一族红线 =
**系统UI元数据（系统提示/积分/进度条/纯数字面板）不得直出，须内化为世界观具象表达** + 能力弱化不得残废化。

**根因1 · 幽灵规则（只查不写）**：全库对照 →
| 审稿器引用 | foundation 里定义？ |
|---|---|
| 铁律一/铁律二/铁律三 | ❌ **全无定义** |
| 铁律四点五 | ✅ |

→ 审稿器拿"提示词里根本不存在的编号"判人。**修复**：把 **铁律一/二/三** 补进唯一源
`foundation.js` 的 `additionalFoundationRules`（执笔/复审同源可见），并加测试断言"审稿器引用的铁律必须有定义"。

**根因2 · 检测器误报**：二审判据原为 `content.includes('系统提示')` → 把
"**不是**系统提示，而是…"判成 critical HARD BLOCK。**修复**：新增 `detectors.systemMetadataLeak()`
——结构化模式（`积分：数字`/`进度条`/`系统提示：`/括注 UI 令牌）**+ 否定前缀豁免**；
并**刻意不收录**「状态栏/属性面板」这类**剧情化 HUD 描写**词（游戏化题材里是合理叙事，收了就是新误报）。
实测：全书定稿命中 2→1（真阳性保留，误报清零）。
