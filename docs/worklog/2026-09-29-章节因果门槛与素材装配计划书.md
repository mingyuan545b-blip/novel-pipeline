## 三、关键结论（施工者必读）

1. **不要重写装配骨架**：`agentDeclarations → contextCommander → agentMaterialScheduler →
   contextAssemblyRecorder` 已是"单点装配"雏形，改动 = 在其上加三层（顺序/缺口/密度）。
2. **先修顺序（P1-4a）**：`materialGate.assertChapterReady` 要求第 1..N-1 章全为 `material-updated`
   才允许第 N 章开工；缺口按章号升序补跑，失败则**阻断且告警**；唯一妥协出口是**显式** `materialDebt`。
3. **禁止静默**：`materialManagerCatchup.js:36-37` 与 `orchestratorPreflight.js:34` 的
   "[补跑失败，跳过]"（直接置 `material-updated`）是"问题反复出现却查不到"的根因，必须在 P1-4a 收口。
4. **规划不超前**：加 `scope:'far'|'near'`——远景粗纲不含素材细节，就近细纲在执行前用**已归档素材**生成。
5. **可追溯**：装配记录加 `provenance{sourceStore, originChapter, lastUpdatedChapter, writtenBy}`
   + `densityReason` + `gaps`，复用既有 `contextTraces` 存储（**不新增表**）。
