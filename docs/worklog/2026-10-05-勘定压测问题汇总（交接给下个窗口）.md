## 二、未修复问题（按严重度）

### 【P0-A】两个实体中心模块**默认 off** → 核心数据全 0
- 证据（本项目 T0 后）：`character-chronicle`=0、`world-scopes`=0、`cross-world-traces`=0。
- 根因：`server/startup.js` 注册时给了默认关闭值：
  - `registerModule('chronicle', {...}, 'chronicleLevel', 'off')`
  - `registerModule('worldScope', {...}, 'worldScopeLevel', 'off')`
  取值来自 `project.settings.chronicleLevel / worldScopeLevel`（`services/pipelineModuleRegistry.js: getModuleConfig`）。本项目未设置 → 'off' → `onPostApproval` 不跑 → 编年史/世界域提取全不产出。
- 修复方向：压测项目初始化时把 `settings.chronicleLevel='full'`、`settings.worldScopeLevel='full'`（前端 ChronicleTab/ScopeGuideCard 已能改，但**初始化默认 off** 是产品层面缺口：新项目实体中心招牌功能默认不出数据）。

### 【P0-B】限知三维度缺 `confidence`/`sourceHow` → 限知树/确信分组/串知全失效
- 证据：本项目 42 条 `knowledge-facts`，**带 confidence 的 = 0**；字段仅 id/level/category/entityId/factText/decayScore/...（无 confidence/sourceHow）。
- 相关：`services/pipeline/steps/knowledgeExtractor.js:54-55` **有**产出 `confidence`/`sourceHow`；但 `services/knowledgeBase/knowledgeAccess.js` 的三维度（certain/suspect/misinformed/unknown）**与 flat knowledge-facts 存储不是同一条链** → 落库丢字段。
- 影响：限知测试点（确信度分组、误信、串知检测）**无数据可验**。
- 待查：素材同步路径 `syncFactsFromMaterials` 是否写 confidence；两套 knowledge 存储是否需归一。

### 【P0-C】素材→实体字段映射缺失 → 角色 10+ 字段全空（用户所指"空5个"）
- 证据（13 个角色实体）：**全空**字段 = `charisma / philosophy / quoteLibrary / entranceDesign / highlightScenes / speakingTone / behaviorRules / craftStyle / relationsSummary / bindsSummary / factionName / tags / locationSlot / bindMedium`；`signatureDetail` 11/13 空。
- 关键对照：**素材正文是完整的**（`岑野` content 1315 字，含 欲望/恐惧/谎言/创伤/方言/魅力/金句/高光）——**是同步丢了，不是没生成**。
- 根因：`server/services/pipeline/outlineEntitySync.js` 只映射 3 个浅字段（`personality`/`speakingTone`/`signatureDetail`，取自 `mat.*` + `extractCharacterStateFromContent`），**完全没有** charisma/philosophy/quoteLibrary/entranceDesign/highlightScenes 的解析映射。
- 连带：`personality` 只落成 `"温柔"`（2 字）——深度门禁 `materialDepthSpec` 未拦住。
- 修复方向：扩 `outlineEntitySync` 映射（从素材正文解析四件套/方言/金句库/高光/魅力/哲学观），并保证 `speakingTone`（方言）必落。

### 【P0-D】装备/功法**无阶段数据**
- 证据：本项目 `item-definitions`=11，**带 `propertiesJson.stages` 的 = 0**。
- 影响：阶段寻址（每阶属性/特效、摘要只存地址）无数据可验。设计文档已将此列为"数据侧待办"。
- 修复方向：生成装备/功法时写入 `stages` + `currentStage`。

### 【P1-E】仆人/宠物系统**无数据**
- 证据：`pet_entities`=0、`servant_entities`=0（素材生成未产出"声仆/宠物"类）。
- 影响：仆人绑定（masterId）/宠物（ownerId）与"主人≠渠道"的归属压测无对象。

### 【P1-F】素材生成链两个缺陷
- **#12 单次超量 → JSON 截断**：一次要求 11 角色+全设定 → `parseJsonResponse` 失败 → `created=0`；拆 3~4 批即成功。（`services/pipeline/outlineGenerator.js: generateInitialMaterials`，maxTokens 32768）
- **#13 非角色素材无 upsert → 整批回滚**：同名唯一约束 `idx_materials_project_type_name` 触发 → 整批 `created=0`。（`saveMaterial` 仅 character 走 upsert）

### 【P1-G】流水线行为
- **#14 门槛拦下不自动续跑**：一次性 `POST /api/pipeline/full` 被 `materialGate` 拦下后任务结束，不自动重试（需外部重触发）。infinite 批量循环不受影响；单章 API 调用方需处理。
- **#15 章长偏短**：ch1 正文 1779 字（题材 `pipelineConfig` 目标 2400–2800）；短章仍被 approved，门禁偏松。
- **relations-empty 警告**：writer/reviser 声明 `relationship` 为必备，但 `relations` 源空 → 日志报"必备素材缺失"。需查 relationship 源映射（`character-relations` mine=3 vs 声明源 `relations`）。

## 五、本轮验证结论（补：P0-A 已实证）

手动调提取接口（绕过模块开关），结果如下——**证明提取器本身是好的，问题就在"模块默认 off"**：

| 调用 | 结果 |
|---|---|
| `POST /api/pipeline/chronicle/:pid/extract`（ch1-3, level=full） | ch1=1 / ch2=2 / ch3=4 条 → 落库 **character-chronicle=6**，8 维字段齐全（stance/daily/psychology/innerConflict/highlights/quotes/deeds/relations/stanceShiftReason） |

**结论**：P0-A 的修复 = 给项目设 `settings.chronicleLevel='full'` + `settings.worldScopeLevel='full'`（或改启动默认），即可让 pipeline 自动产出；**无需改提取器代码**。

**新增发现（#17）**：world-scope 记录里 `worldName="腔市"` 但 `worldId="main-world"` —— 世界**名称↔id 未归一**（腔市应是 `jie-qiangshi`）。会影响"归属数按世界分组/契约归一"的准确性。定位：`worldScopeExtractRunner` 的世界名→id 匹配。
