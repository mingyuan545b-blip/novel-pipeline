## 二、许可证机器码（根因 + 修复）

**症状**：`/api/pipeline/*` 全部 403「「pipeline」功能需要专业版会员」，上下文装配图整页打不开。

**根因**：`data/license.json` 的 `machineId` 与当前机器不符（`5992ef9b…` vs `62da6520…`）。
`license.js:getMachineId()` 用 `hostname + CPU型号 + os.totalmem()` 哈希 → 内存变化即失效。

**修复**：
- 新增 `server/services/machineFingerprint.js`：优先 OS 级稳定标识（Windows MachineGuid /
  Linux /etc/machine-id / macOS IOPlatformUUID），兜底 `hostname + CPU + arch`，**移除 totalmem**，进程内缓存；
- `license.js` 改用该模块，`checkMembership()` 的 mismatch 分支附带 `machineIdSource` 便于诊断；
- 重新激活：`activateLicense('NP-PRO-testlicense1234567890')` → 新指纹 `9e92e536…`，`/api/license/status` 恢复 `pro`。

> 顺序注意：**先重启后端（新算法）再激活**，否则激活写入的是旧算法指纹。

## 四、实体中心分主次（改造）

**问题**：12 个角色全是一模一样的行，默认按创建时间倒序 → **主角「沈砚」（出场16次）沉到最底部**；
配角/NPC 混排无分组；右侧详情区大面积留白。

**改造**：
- `characterListUtils.js`：等级分组（主角/配角/NPC/未标注）+ 组内排序 + 搜索/等级筛选（纯函数）；
- `CharacterListPanel.jsx`：搜索框 + 排序（默认"重要度=等级+出场"）+ 等级 chips（带数量）+ 分组标题；
- `CharacterRow.jsx`：分级视觉（主角金边大卡 44px 头像 / 配角蓝边 36px / NPC 收敛 28px）；
- `CharacterOverview.jsx`：未选中角色时显示等级分布 + 出场 Top6（替代原来的大片留白）；
- `characterList.css`：新样式（不改动其他 tab 的既有样式，降低回归面）。

**顺手修掉的真实缺陷**：`GenreStateSection.jsx` 用**题材 id** 当**项目 id** 请求
`/api/projects/:id/genre-constraints`（每次打开实体中心一条 404，且返回值写进从未读取的 `_genreSchema`）→ 已删除该无效请求。详见陷阱 #117。
