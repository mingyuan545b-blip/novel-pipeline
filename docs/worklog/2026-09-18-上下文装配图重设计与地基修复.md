# 2026-09-18 上下文装配图重设计 + 上下文地基修复

## 目标（用户原话摘要）
1. 四五百万字：逻辑/战力/伏笔不崩
2. 素材库/知识库/实体中心每个功能真正用上，不是一次性大杂烩
3. 「上下文电路」改名：它实际功能=看每章用了哪些提示词/资料、什么层级/信息密度、哪些数据传入或丢失
4. 全项目功能数据流通核查（只读）
5. 新项目（有趣设定、无人机味/烂大街名/低俗套路）跑通5章 + 前后端联动无bug
6. 地基优先，可分阶段验证

## 审计发现的根因（已实测）
- P0-A `unifiedBudgetPool.calculateBudget`: `totalAllocated = availableBudget - remaining` 算错 →
  10个Agent全部恒判 red/force-minimal → 所有素材类型强制 L0
- P0-B 实体 L0 输出仅 `名字 | 角色定位`（无性格/身份/背景）→ 人设崩
- P0-C `MODEL_BUDGETS` 硬编码且缺实际模型；`totalBudget` 语义混用（字符 vs token）
- P0-D contextCommander 产出的 servantDecisions/timelineContext/techniqueSchedule/decisionLog 无下游消费
- P0-E 长篇章：CHAPTER_PHASES 仅覆盖1-99章；30章/卷硬编码10处
- P0-F 记忆 L0-L4 只被路由展示，未注入 prompt
- P0-G 题材 genre 未贯穿 resolveContext / scheduleTechniques → 题材元素组合失效
- P0-H contextMapBuilder 基于静态声明，非逐章真实决策 → 电路图与实际脱节

## 五章E2E中发现的新问题（未修，需决策/后续）

### 已修复
- **字数系统性不足**（根因）：writer prompt 场景下限硬编码 400/600/500/400=1950字，
  而硬性最低 2500 → 提示词自相矛盾，模型锚定1950，成稿稳定落在1900~2479被退回。
  已改为 `config/writerLengthPolicy.js` + `sceneFloorInstruction.js` 由 wordConfig 派生
  （实测 ch5 2235→2594 approved、ch3 2473→2501 material-updated）

### 未修（按优先级）
1. **人物关系生产端断链（P0）**：`outlineRelationCreator` 路径1只从 `type='relationship'`
   素材提取，而素材库从不存在该类型；路径2靠中文正则（违反原则3），实测新项目前3章产出0条关系。
   消费端已修（relationMaterialLoader 改读 character-relations），但**生产端仍缺**：
   应由 material-organizer/material-manager 用 LLM 输出关系并写入 character-relations。
2. **角色素材深度不足（P1）**：4个角色素材均 <400字（实测 0/4 ≥400字），
   直接削弱"人设不崩"。需查 material-registrar 的角色素材生成深度配置。
3. **分层记忆 L0-L4 冗余（P2）**：`services/memory/*` 的 core/active/recent/compressed 层
   只有UI读取，无prompt消费路径；长期记忆实际由 knowledgeBase.memoryPyramid(M0-M3) 承担。
   建议二选一（原则1 单一数据源）：要么把 L4 卷摘要接入 memory-pyramid slot，要么删除该模块。
4. **守卫提示在本项目无输出（P2）**：时间线矛盾/战力/伏笔/角色弧在3-5章规模无输出，
   需在有冲突数据的项目复验，不能判定为bug。
5. **licence 机器绑定（需用户决策）**：`getMachineId` 含 totalmem，内存变化导致
   终身 pro key 被降级为 free → 整个 /api/pipeline 全被拦（本次实测 machineId 不匹配）。
   已用原 key 重新激活恢复；建议改为"key可验证即有效"，机器绑定只做提示。
6. **字数达标偏紧**：ch3 2501/ch4 2553 仅擦线，建议项目 wordConfig 的 rejectMin 略低于 minWords
   留出抢救区（当前 rejectMin==minWords==2500，可救区为0）。
