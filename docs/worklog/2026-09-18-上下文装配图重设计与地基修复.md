# 2026-09-18 上下文装配图重设计 + 上下文地基修复

## 目标（用户原话摘要）
1. 四五百万字：逻辑/战力/伏笔不崩
2. 素材库/知识库/实体中心每个功能真正用上，不是一次性大杂烩
3. 「上下文电路」改名：它实际功能=看每章用了哪些提示词/资料、什么层级/信息密度、哪些数据传入或丢失
4. 全项目功能数据流通核查（只读）
5. 新项目（有趣设定、无人机味/烂大街名/低俗套路）跑通5章 + 前后端联动无bug
6. 地基优先，可分阶段验证

## 审计发现的根因（已实测）
- P0-A `unifiedBudgetPool.calculateBudget`: `totalAllocated = availableBudget - remaining` 算错 →
  10个Agent全部恒判 red/force-minimal → 所有素材类型强制 L0
- P0-B 实体 L0 输出仅 `名字 | 角色定位`（无性格/身份/背景）→ 人设崩
- P0-C `MODEL_BUDGETS` 硬编码且缺实际模型；`totalBudget` 语义混用（字符 vs token）
- P0-D contextCommander 产出的 servantDecisions/timelineContext/techniqueSchedule/decisionLog 无下游消费
- P0-E 长篇章：CHAPTER_PHASES 仅覆盖1-99章；30章/卷硬编码10处
- P0-F 记忆 L0-L4 只被路由展示，未注入 prompt
- P0-G 题材 genre 未贯穿 resolveContext / scheduleTechniques → 题材元素组合失效
- P0-H contextMapBuilder 基于静态声明，非逐章真实决策 → 电路图与实际脱节
