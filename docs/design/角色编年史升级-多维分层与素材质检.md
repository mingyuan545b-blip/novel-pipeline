# 角色编年史升级：多维分层 · 台词工艺 · 素材质检（设计提案）

> 触发：用户反馈（2026-10-04）。诉求要点：
> ① **编年史分类太粗**——只提取"立场/内心矛盾/语录/事迹"，缺**日常、心理变化、立场变化、高光时刻、特定情景的名言**；
> ② 名言要能成套（参考《星游记》励志发言、《蛊真人》方源"路就在脚下"、龙公的人格魅力、
>    《英雄联盟》卡蜜尔"我曾踏足山巅，也曾进入低谷，二者都让我受益良多"、《凡人修仙传》"人生如棋，落子无悔"）；
> ③ 问：这些"设定 + 人物层次密度"**要不要新增一个"台词/人物/场景设计 Agent"**，还是丢给**素材管理 Agent**？
> ④ 如何保证**质量下限**、如何**校验素材质量**、**开新篇**怎么设计流程、如何保证质量下限。
>
> 状态：**P0/P1 已施工 / P2 部分施工**（见 §八 实施记录）。落地按 sop/03（新功能）/sop/07（Agent 变更）/sop/12（创作工艺）执行、sop/10 落盘。

## 零、一句话结论

**不新增运行时 Agent。** 台词/人物/场景属于**两层已有职责**：
- **前期设计层**（开写前）→ 新增**离线「人物工艺设计器」**（脚本/初始化步骤，不是 pipeline agent）；
- **运行期维护层**（写作中）→ **扩 material-manager** + **扩 chronicleExtractor 维度**。
理由：pipeline 已有 6 Agent（intent-planner/writer/reviser/editor + 双审核 + material-manager），
runtime 加第 7 个只会加 token、加协调面；而"台词/高光/场景"本质是**素材的定义与生命周期**，正是 material-manager 的既有边界。

## 二、编年史维度升级（可执行）

把编年史从"4 维"升为**8 维**（每维独立字段，缺省空串/空数组，向后兼容）：

| 维度 | 字段 | 说明 | 适用档位 |
|---|---|---|---|
| 日常 | `daily` | 生活化细节/习惯/口头禅/在副本里的日常行为（让 NPC"有自己的日子"） | basic+ |
| 心理变化 | `psychology` | 心理状态变化曲线（怕→赌→认命…），与 `innerConflict` 分开（前者是变化，后者是矛盾） | basic+ |
| 立场 | `stance` | 现有，保留 | minimal+ |
| 立场变化 | `stanceShiftReason` | 现有，保留（从 X 到 Y + 原因） | full+ |
| 高光时刻 | `highlights[]` | `{scene, what, why}`——本章角色"发光"的名场面（可回流实体素材） | full |
| 名言/台词 | `quotes[]` | 升级为 `{scene, quote, why, chapter}`（见 §三 质检） | full |
| 事迹 | `deeds[]` | 现有，保留 | full |
| 关系变化 | `relations[]` | `{target, from, to, reason}` 本章关系变动 | full |

- 档位从 `off/minimal/basic/full` 扩为 `off/minimal/basic/full/rich`（`rich` = 8 维 + 高光回流），
  或直接把 `full` 扩成 8 维（二选一，UI 的 `CHRONICLE_LEVELS` 同步）。
- **回流规则**：`highlights`/`quotes` 提取后，去重合并进 `entities.quoteLibrary` / 新增 `entities.highlightScenes`——
  让"编年史"从只读展示变成**素材增量源**（对齐《实体中心-重规划》"单一源"原则，实体为唯一源，编年史是过程记录）。

## 三、台词工艺与质量下限（核心）

### 3.1 一句好台词的四要素（质检对象）
```
{ speaker: 说话人, scene: 适用场景, quote: 原文, why: 为什么记得住(记忆点), chapter: 首次出现章 }
```
- **原文不可改写**（`quotes.quote` 必须与正文逐字一致，可回溯 `chapter`）；
- **场景必填**（"什么处境说这句"；否则台词只是鸡汤）；
- **记忆点必填**（`why`：这句话驱动了人格/立场/命运的哪一环）；
- **禁止清单**（反 AI 味，复用 sop/12 §五）：禁段尾俏皮话、禁抽象升华、禁现代网络梗乱入。

### 3.2 三道质量闸门（保证下限）
| 闸门 | 位置 | 规则 |
|---|---|---|
| 素材深度门禁 | 写库前 | 复用 `materialDepthSpec`：`金句库` minChars≥20 + 场景标签；`charisma`/`philosophy`/`entranceDesign` 已有校验 |
| 台词专属校验 | 写库前 | 新增 `validateQuotes.js`（纯函数）：四要素非空 + 原文回查章节正文 + **跨章语义查重**（同义台词不重复入库） |
| 老书虫门禁 | 审读层 | 复用 sop/12 Stage7：台词引入 `character-break`（台词与人设矛盾）→ hardBlock |
| 误报对照 | 回归 | 沿用 sop/12 的对照组实验（好作 vs 问题作），新检测器必须报"真阳性"且不误伤好作 |

### 3.3 校验素材质量（用户问）
三层校验，缺一不可：
1. **非空 + 非模板化**（`materialDepthSpec`：minChars + qualityHints，防"写了'核心欲望'四字就过"）；
2. **结构化完整**（名言四要素、高光三要素 scene/what/why）；
3. **可回溯 + 去重**（原文回查章节、跨章语义查重）；
→ 全部**接入 `contractValidator` HARD BLOCK**（"检测而不拦截等于没检测"，PROJECT_STANDARDS §B-11/12）。

## 四、Agent 决策：新增 or 复用？

**结论：不新增运行时 Agent；扩两处 + 新增一个离线设计器。**

| 方案 | 评价 | 采纳 |
|---|---|---|
| A. 新增"台词/人物/场景设计 Agent"（runtime） | pipeline 增第 7 个 Agent：token↑、协调面↑、与 writer/material-manager 职责重叠；且"设计"是**开写前**的事，runtime agent 用不上 | ❌ |
| B. 全丢给 material-manager | material-manager 已是**素材生命周期**所有者，天然承接"台词/高光入库/去重/归档"；但**开写前的"设计"**不是它的职责 | 部分 ✅（运行期） |
| C. **离线「人物工艺设计器」+ 扩 material-manager + 扩 chronicleExtractor** | 开写前离线产出人物卡/台词库/高光场景（可人审）；运行期由 material-manager 维护、chronicle 增量提取 | ✅ |

**C 的落点**：
- **离线设计器**：`scripts/designCharacterCraft.js`（或纳入项目初始化步骤 `generate-materials` 的一个 stage），
  产出：主角四件套（欲望/恐惧/谎言/创伤）+ 配角三件套 + `quoteLibrary` + `entranceDesign` + **`highlightScenes`（新增字段）**，
  直接落 `entities`；可人审后再开写（对齐 sop/12 Stage0-2）。
- **material-manager**：接收 chronicle 回流的 `quotes`/`highlights`，做**去重合并 + 生命周期**（停更/归档），不新增 Agent。
- **chronicleExtractor**：扩 8 维（§二）。

## 十、什么是高光 / 名言 / 魅力：把"判定标准"写进 prompt（2026-10-08）

> 触发：用户反馈（2026-10-08）——「编年史的高光时刻/名言怎么定义的？看看凡人修仙传『人生如棋，落子无悔』、
> 英雄联盟『我曾踏足山巅，也曾坠入低谷，二者都让我受益匪浅』怎么写人物高光/人格魅力/名言名梗？
> 再看看上一个项目写的什么玩意，agent 该怎么改、什么提示词、什么结构，才能让 AI 认识什么是高光、什么是魅力、什么是名言，而不是流水账？」

### 10.0 取证：上一次编年史产出到底烂在哪（本仓库真实数据）

对 PG `character_chronicle`（项目 `7d3e3e66` / `e5f0c24e`）逐条核验：

| 症状 | 实证 | 根因 |
|---|---|---|
| **why 是评论腔，不是记忆点** | 高光 15 条里 **10 条 why** 以"展现了…/体现了…/确立了…/立住了…"开头 | 提示词只说"为什么是名场面"，**没给"什么不算"**，LLM 默认写读后感 |
| **what 是剧情摘要，不是名场面** | "使用空白勘定笔在桌面划出蓝光弧线，制造临时规则屏障冻结探员行动权，趁乱带走流浪汉。" | 提示词把 what 定义成"做了什么/高光点"——**与 deeds 重复**，必然退化成事件复述 |
| **名言收进过场句** | quotes 含 `"上车。"` `"进去了。"` `"几多钱？"` `"莫搞。"`；其中 `"进去了。"` 的 why 直接是空串 | 提示词只说"缺场景/记忆点的鸡汤不收"，**没有"过场/功能句不收"这一条** |
| **结构字段产不出来** | `speaker` 100% 为空、`chapter` 100% 为 0 | 字段列在 JSON 骨架里但没在"规则"里要求；解析端也没有回填 |
| **无"代价/反差"维度** | 高光只有 scene/what/why 三格 | 没有 cost 字段，于是"赢要付代价"这条最重要的戏剧性无处落笔 |

> 结论：不是模型不行，是**提示词只给了"要什么"，没给"什么不算"**——没有反例、没有判定测试、没有自检。
> 同时 `quotes/deeds/highlights` 三者边界重叠（都是"做了什么"），必然写成流水账。

### 10.1 判定标准（可执行，已落代码）

标准单一数据源：**`server/services/craftQualitySpec.js`**（定义 + 正反例 + 禁词表 + 提示词块）。

**高光四问（全过才算高光）**
1. **可截图**：一句话能画出画面——谁、在什么处境、做了什么动作或说了哪句原文。
2. **只有他会做**：把名字抹掉换成别人，这个选择就不成立或不好看（去名测试）。
3. **有代价/反差**：他失去了/放弃了/背负了什么（赢要付代价，输要有姿态）。
4. **不可逆**：此后他的立场/关系/命运变了（→ 与 deeds 的分界：deeds=做了什么，高光=哪一刻他成了他）。

**名言三问（全过才算名言）**
1. **去语境**：单独贴出来还站得住（"上车。""进去了。"这类过场句不算）。
2. **反推**：不看名字也能推出说话人的身份/处境/脾气。
3. **重量**：它承载了他的信念、恐惧、谎言或命运抉择。

**人格魅力**＝压力下的选择函数，固定写成 `当【处境】时，他宁可【做X】，也不【做Y】`；禁止"智勇双全/游走灰色地带"式形容词堆砌。

**正例（附真实出处，供 prompt 当 few-shot）**
- 《凡人修仙传》：何仙师临终留给韩立**"人生如棋，落子无悔"**（动画在韩立离开天南、与王蝉擦身而过处引出）。
  它被记住不是因为漂亮，而是因为**挂在"不可回头的人生节点"上**——台词必须挂在处境与命运上。
- 《英雄联盟》卡蜜尔：**"我曾踏足山巅，也曾坠入低谷，二者都让我受益匪浅。"**
  记忆点在于她把"跌入低谷"重估为收获，一句话定住冷傲与阶级观（有代价、不可逆）。

**反例（取自本项目真实数据，直接写进 prompt 的"禁止"段）**
- 剧情摘要式 what；评论腔式 why（展现/体现/凸显/彰显/标志着/生动/侧面/营造/渲染/立住/暗示/铺垫/推动剧情/刻画）。

### 10.3 边界与遗留

- **chronicle 仍存原始提取**（不过滤），过滤发生在**回流实体**这一步：编年史是"过程记录"（可审计），实体是"单一源"（只收合格品）。
- **garbage in 问题未解**：提取是**事后**的，若正文本身没有高光，再好的 prompt 也抽不出来。
  待办 **M11「高光/名言配额」**：在 writer 侧要求每章为视角角色留 ≥1 个"可截图瞬间"（落点=动作或台词原文），
  并把 `entities.highlightScenes / quoteLibrary`（设计期产出）注入 writer（当前 `formatters.js` 已注入，但设计期字段普遍为空）。
- 名梗（meme）维度未纳入编年史：现有 `data/meme-lexicon` 是**喜剧素材**（跨界混搭/文学戏仿），与"角色名言"是两回事；
  若要做"角色口头禅/名梗"，应新增 `catchphrase` 维度并复用 `daily`（口头禅）——**待用户确认是否需要**。
- 存量数据：老章编年史的评论腔 why 不会被自动修；可选择重跑章节提取，或跑设计器补齐实体工艺字段。
