# 实体中心重规划：素材单一源 + 预处理入口 + 生命周期

> 触发：用户第二/三轮反馈（2026-09-27）。用户明确实体中心的定位与两个目的：
> ① **状态追踪作为后续章节素材加载的来源**，避免"多重定义源"混乱；
> ② 实体中心 = **素材管理与预加载处理**（素材关系 / 上下级归属 / 逐章状态），
>    并解决"报废素材不回收归档 = token 黑洞"；其他 Agent 直接读**预处理结果**、不再逐章拼凑，
>    避免多源头污染，且**出问题能直接看到**。
>
> 结论：**需要改造（结构性），不是小优化**。本文是方案与分批计划，按 sop/02/03 执行、sop/10 落盘。

| 世界观 | `materials.worldview` 30 **vs** KV `worldview` 34 | **双存**；且 KV 主题**碎片化** |

## 二、根因（结构性）

1. **三条链各自为政**：定义层被拆在 `materials` / `item-definitions` / `character-state-KV`，同一事实多处落盘；
   各 Agent（writer/reviewer/planner）按需各自拼装 → 来源不一致 + 重复注入（token 黑洞的一半在这里）。
2. **状态层无约束**：字段不受题材白名单约束、且把"等于默认值"的字段也持久化 → 无关字段污染 prompt 与 UI。
3. **无生命周期/区间**：素材/道具没有"有效章节区间 + 有效状态"，报废后仍被后续章节加载。

## 三、目标架构

- **定义层（Definition）= 每类唯一源**
  - 装备/道具/功法 → `item-definitions`（唯一）；`materials.equipment` 停写并迁移合并
  - 世界观/势力/地点/规则 → `materials`（唯一）；KV 只存**逐章状态变化**，不再存"定义"
  - 角色身份 → `entity_registry`（唯一）；逐章状态 → `character-states`；`materials.character` 停写
- **状态层（State，逐章）**：`state-kv-index`/`character-states`，字段受**题材白名单**约束，
  **不持久化"等于默认值/空值/无关"字段**（读写两侧同一套规则）
- **预处理入口（单点装配）**：`materialStateAssembler(projectId, chapterNumber)` 输出
  `{ 素材清单, 层级(定义/状态), 是否命中本章区间, 关系与归属, 生命周期有效性, token 预算 }`；
  其他 Agent **只调用它**（结果落 context-assembly，可观测）
- **生命周期**：所有素材/道具加 `state`(active/suspended/retired) + `activeFromChapter/activeToChapter`；
  人物牺牲、装备报废 → `retired`；加载时按"当前章 ∩ 区间 ∩ 有效状态"过滤

## 四、改造清单（分批）

### P0（低风险，立刻见效）
1. ✅ **与题材无关字段源头过滤**：`getGenreImportantKeys` 兜底改为题材中性字段（去掉 hp/combatPower）；
   状态/KV 读取沿用 UI 同一套 `visibleFields` 规则（默认值/空值/无关不输出）。
2. ✅ **生命周期（落点修正 → 落在被加载的 `materials`）**：
   > 实测发现：`item-definitions` **只有 UI/迁移脚本在用，管线并不读它**，真正被 Agent 加载的是
   > `materials`（equipment→plot 组）。若把生命周期加在 item-definitions 上，**省不到 token**。
   > 故落点改为 `materials`：

   - 新增 `server/services/materialLifecycle.js`（纯函数）：`isMaterialActiveAt`（归档/报废/区间）+
     `lifecycleLabel` + `normalizeLifecyclePatch`；无章节上下文（建索引）时不裁剪区间（保守）。
   - 加载链过滤：`materialIndex.rebuildIndex/getMaterialsForScene/...`、`materialBudgetCalc` 均改用该判定
     → **区间外/归档/报废素材不再进入本章上下文**。
   - 迁移脚本 `scripts/migrateMaterialLifecycle.js`（默认干跑，`--project`/`--apply`/`--json`）。
   - UI：装备/功法卡片显示「生命周期：常驻 / 已归档/报废 / 第x–y章」；展开可**归档/恢复 + 编辑章节区间**，
     写入**同名 materials 条目**（单点写被加载的源，避免双写）；默认隐藏已归档（可勾选查看）。
   - 测试：`materialLifecycle` 7 条 + `materialBudgetCalc × lifecycle` 接线 1 条。
3. ✅ **双存止血（写入侧 + 历史数据 + 可观测）**：
   - **装备/功法内容不再复制**：`item-definitions` 曾是 `materials` 内容的拷贝（只为承载 binds）。
     现 `outlineEquipmentBinds.buildItemDefinition` / `materialBindProcessor` 创建定义时
     **不再复制 4 级描述**，改为只留身份 + `materialId` 回指；并按 name **幂等复用**（不再产生重复定义）。
     前端卡片在定义描述为空时**回落读素材内容**（`material.description/currentContent`）。
   - **世界观主题归一**：新增 `server/services/worldviewTopics.js`（`normalizeTopic/resolveTopicKey`：
     剥括号/斜杠后缀 + 同义尾缀 机制|协议|模式|体系… + 互含匹配，长度比 ≥0.6 防过宽合并）；
     `materialItemProcessor.processWorldviewChanges` 写入前把新主题**归到既有主题**（KV+素材库合集），
     命中则更新既有、未命中才新建 → 不再逐章制造碎片。
   - **可观测**：`scripts/verifySourceUniqueness.js`（只读体检：装备/功法双存、世界观双存、定义是否仍含内容）；
     `scripts/migrateDefinitionContent.js`（默认干跑，`--apply` 清空复制内容并回指素材）。

## 五、验收指标

- **来源唯一性**：同一素材在装配报告中只出现 1 个来源；
- **黑洞归零**：报废/超期/区间外素材不再进入上下文（Token 面板对比"分层记忆/素材"占比下降）；
- **单点装配**：Agent 上下文来源= `materialStateAssembler`，装配图可查；
- **字段纯净**：KV 无默认值/无关字段（服务端与 UI 一致）；
- **可观测**：体检面板 0 未知项。
