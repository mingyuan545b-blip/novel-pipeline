# 实体中心：信息密度分级与阶段寻址

> 触发：用户反馈（2026-10-03）。诉求要点：
> ① 装备/线索**点卡片不改变左卡，细节只在右栏**；卡片过大、重叠，需紧凑化重排；
>   右栏描述被挤成一列长条，标签需中文化。
> ② 摘要卡片过大且**完全展开** → 需折叠，默认只给「概要」。
> ③ 疑问：「主角生命值 90%」是什么？摘要是不是把所有数据堆一起？
> ④ 信息深度随场景不同：功法过滤只需大概；战斗对敌要 **PK / 强弱对比**；
>   功法每一层特效不同、装备每一级属性不同（差异大时每级是独立数据）。
>   → **摘要只保存指向「当前阶段」属性数据的地址**，平时只读概要，需要时再载入对应阶段的详细版本。

| 位置 | 问题 | 处理 |

## 二、信息密度分级（Definition Density）

复用定义层已有的四级描述（`item-definitions`），UI 默认加载最低密度：

| 层级 | 字段 | 场景 |
|---|---|---|
| 概要 briefly | `briefDesc` | 常规行文引用（**默认**） |
| 摘要 summary | `summaryDesc` | 交代关键设定 |
| 详细 detail | `detailDesc` | 关键剧情 |
| 设定 lore | `loreDesc` | 背景沿革，按需加载 |

后端 `itemDefinition.getDescForBudget(defId, tokenBudget)` 已按 token 预算选层；
前端 `definitionLevels.js` 暴露可用层级 + token 估算，详情栏以 chips 切换。

## 三、阶段寻址（Stage Addressing）

**问题**：功法每层特效不同、装备每级属性不同；差异大时每一级是**独立数据**，
不该把「升级前后」当同一份描述。

**方案**：结构化阶段数据放 `item-definitions.propertiesJson`：

```jsonc
{
  "currentStage": "二阶",              // 可选：显式当前阶段（缺省按章节推断）
  "attributes": { "攻击": "+12", "特效": "破甲" },   // 当前阶段属性快照（概要可指向）
  "stages": [
    { "key": "一阶", "label": "一阶·淬体", "chapter": 3,
      "attributes": { "攻击": "+4" }, "effects": ["微光"], "desc": "……" },
    { "key": "二阶", "label": "二阶·凝罡", "chapter": 12,
      "attributes": { "攻击": "+12", "特效": "破甲" }, "effects": ["罡气外放"], "desc": "……" }
  ]
}
```

- `definitionLevels.js`：`stagesOf` / `attributesOf` / `resolveStageKey(item, stages, currentChapter)`。
- 当前阶段推断：优先 `propertiesJson.currentStage`，否则按章节落到 `chapter ≤ 当前章` 的最近阶段。
- UI：详情栏「成长阶段」chips，标 ⭐当前 + 章节；点击某阶段才载入其 `attributes/effects/desc`。
- **摘要只存地址**：卡片/摘要给的是「概念 + 指向当前阶段」，不是全量属性；
  需要 PK / 升级对比时，逐阶段点选即可横向比较（升级前后就是相邻两个 stage）。
- 无 `stages` 数据时优雅降级：只展示密度分级描述，并提示可在 `propertiesJson.stages` 补数据。

## 四、摘要 = 引用，不是堆叠（Summary as Reference）

- `summaryGroups.js` 把字段分为：**核心设定**（身份/阵营/性格…，摘要主体）、
  **关系与所有物**、**运行时状态**（生命值/战力/位置…，**易变，来自状态追踪，非设定摘要**）、其它。
- 卡片默认只显示「概要」= 非运行态代表字段 + 字段数 + 运行态计数；点击展开分组详情。
- 卡底展示「⤷ 引用 状态库 · 第 N 章」：说明摘要保存的是指向状态库的**引用地址**，详细版本按需载入。
- 「主角生命值 90%」属**运行时状态**（`hp`，`trackAllFields` 角色才会全字段落库），
  已从摘要门面移除、单列并标注来源，不再与稳定设定混在一起。
